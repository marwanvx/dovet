### Test-quality rules

A test must prove the feature works, not just turn CI green:
- **Test what the user would see,** through the module's public surface: files on disk, process exit codes, the request bytes sent, the events logged, the text returned to the model. Never assert only that a function was called or a value is defined.
- **Don't fake the thing being tested.** Mocks are allowed only at the edges the test layer names (the scripted model, the fixture server, a fake clock); file, process, sandbox and git behavior is tested with real files and real processes in temp directories.
- **Provider behavior comes from recorded real traffic** (fixtures recorded from the live API), never from hand-written responses that merely match what the code expects.
- **Red before green:** every new test is run before the implementation and must fail for the right reason; the failing output is part of the PR ([build loop](../workflow/build-loop.md) step 6).
- **Proof by breaking:** the reviewer breaks each criterion's implementation and the tagged test must fail ([build loop](../workflow/build-loop.md) step 7). A test that survives a broken feature is rejected.
- **A test run leaves nothing behind.** `bun run test` runs the suite with its temp directory set to a fresh private one and fails, naming them, if any `dovet-tool-*` workspace is left in it (`workspace()` from `src/tools/test-context.ts`; the removal after each test is a preload in `bunfig.toml`, because a hook registered inside an imported module covers only the first test file that loads it).
- No skipped or focused tests (`.skip`, `.only`, `.todo`) on `main`; no snapshot test as the only check of a behavior unless the snapshot was reviewed against the spec; no assertions weakened to make a test pass (AGENTS.md).
- **Beyond unit tests, real use decides:** platform tests run real shells on all three OSes; the nightly suite calls the real APIs; each milestone's exit evidence includes real end-to-end work (M1: 10 real coding tasks; M3: the owner's daily use); evals run hidden tests the agent never saw.

### Additional required tests

- Release binary in a directory containing a planted `.env` and `bunfig.toml`: assert neither was loaded (env var absent, config ignored).
- Compatibility corpus: ~200 cases built from Claude Code's documented permission examples ([permissions](permissions.md) AC-PERM-14); Dovet's decisions must match, except the differences §0b makes on purpose (listed in the corpus).
- Early read-only execution: results discarded on refusal / truncated tool call / interrupt; ordering preserved.
- Resume after a Dovet upgrade: a session created with older templates replays byte-identical request prefixes (stored epoch header bytes).
- Snapshot isolation: the user's `.git` directory is byte-identical before and after 100 snapshots.
- Open Responses conformance: the official acceptance tests run against each supported server in nightly CI (where reachable).

**Session-API tests (from M1):** with a scripted model (`MockLanguageModelV4` + `simulateReadableStream` from `ai/test`, so no HTTP is involved), a scripted client drives `Session` the way the TUI will (answers permission prompts, questions and plans; interrupts mid-stream; queues input), so interactive flows are tested before the TUI exists. Headless alone would never exercise them (it auto-denies).
**Multi-session test (from M1):** two sessions in one process ([interfaces §9](interfaces.md)).

**Permission corpora:** `policy/testdata/bypass-corpus.jsonl` (commands that must never be auto-approved) and `false-prompt-corpus.jsonl` (commands that must not prompt), seeded from known bypass and false-prompt cases in coding agents (see [research log §F-08.4](../background/feature-research.md)) and extended with each Dovet bug. Every case is run on every PR, for Bash and PowerShell.

**Shell analysis agrees with bash (differential, AC-PERM-20):** a seeded generator in the test (`test/adversarial/bash-differential.test.ts`; no library, so a failing seed reproduces with nothing else installed: QUESTIONS Q103) builds shell texts from quotes, backslash escapes, split command names, `${…}` operands, `$( )`, backticks, `<( )`/`>( )`, here-documents, comments, arithmetic, subscript assignments, pipelines of one to four stages and `&&`/`||`/`;`/newline lists. Every command name is a stub shell function that records its argv (`command_not_found_handle` records the rest). The texts run under the bash Dovet runs commands with ([tools §5.3](tools.md)); every recorded argv must appear in the analysis's `commands` (a computed word stands for any run of recorded words, a leading assignment is stripped), or the analysis must be unparsed; more than half the texts must record a command and more than a fifth must be analyzed, so the comparison can't go empty. `bun run check` runs 2,000 cases from a fixed seed; the nightly job runs 100,000 from a random one (`DOVET_DIFF_CASES`, `DOVET_DIFF_SEED`) and prints each failing text with its seed; the session that fixes it adds the text to `bypass-corpus.jsonl` with its source. The first version of this check (a `printf '<%s>'` comparison over random backtick bodies, run by hand in F84) found F85 in minutes; this one found the here-document end and the escaped-blank gaps on its first run.

**Prompt checks:** a test asserts that the system prompt contains the behavior rules (safety, scope, verification, honesty, untrusted content) and that no prompt file names a vendor or a vendor-only tool. A prompt-snapshot test fails on any change to an assembled prompt, so every wording change is a reviewed diff. Evals run the same tasks on several model families (including a small local model) with the one shared prompt and tool set; per-family results decide SPIKE-13.

**Docs check (every PR):** `bun run docs:check` (`scripts/check-docs.ts`) fails on an out-of-date "Before you build" box, a broken link, a duplicate or unknown criterion ID, a criterion placed in no task or in several, an unknown task dependency, or a task whose Read link names a section that doesn't exist.

**Recording fixtures:** `bun run record <scenario>` runs a scenario against the live API once (with budget) and saves the request/response pairs (secrets stripped). Fixtures are re-recorded when a provider changes behavior; diffs are reviewed like code.

**Coverage targets:** `policy` and `store` ≥ 90% lines, `agent` ≥ 85%, `tools` ≥ 85%. Coverage is a floor, not a goal; every acceptance criterion has a permanent ID (`AC-<SPEC>-<n>`, e.g. `AC-TOOLS-04`; IDs are never renumbered, removed criteria are struck through, new ones get the next number) and maps to at least one test tagged `// spec: AC-TOOLS-04`. A script fails CI if a tag names an unknown ID, or if a criterion listed under **Done when** of a task marked `done` in `docs/plan/tasks/` has no tagged test (criteria of tasks not built yet aren't checked, so CI is green from the first PR). At each milestone's exit check, every criterion of that milestone must be covered.

### Free test provider: NVIDIA

The owner has a free NVIDIA API key (`NVIDIA_API_KEY`, 2026-10-13). It is the provider for **live smoke tests and for recording fixtures** when a test needs a real model without spending: base URL `https://integrate.api.nvidia.com/v1`, OpenAI Chat Completions, `@ai-sdk/openai-compatible`, models.dev record `nvidia` (docs: https://docs.api.nvidia.com/nim/). Keep the scripted model for every PR; use this provider for nightly or on-demand runs only (about 40 requests a minute; free limits and models change).

- **The model list is not a list of working models.** `GET /v1/models` includes retired and outdated models that fail (a retired Qwen endpoint is one known case), and models.dev's `tool_call` flag is catalog data, not a live check. Before relying on a model, probe it: one tiny chat request and one tool-call request, `tool_choice: "auto"` ([ADR-14](../plan/decisions.md)). Record the working set in the test's own fixture or config, with the date, and re-probe when a run fails with 404 or "function not found".
- **Starting group (owner's list, 2026-10-13; picked for recency and tool calling, not benchmarked; the probe decides).** The endpoint's other models are retired, older than 2026, not chat models (embeddings, safety, vision, parsing), or older code models without tool calls.

  | Tier | Model id | Released | Why |
  |---|---|---|---|
  | Strong, slow | `moonshotai/kimi-k3` | 2026-07 | Newest Kimi, 1M context |
  | Strong, slow | `z-ai/glm-5.3` | 2026-08 | Newest GLM, 1M context |
  | Strong, slow | `deepseek-ai/deepseek-v4.1-flash` | 2026-09 | Newest DeepSeek, 1M context |
  | Strong, slow | `nvidia/nemotron-3-ultra-550b-a55b` | 2026-06 | Largest NVIDIA model |
  | Fast | `z-ai/glm-5.3-flash` | 2026-08 | Quick check of the GLM family |
  | Fast | `nvidia/nemotron-3.5-lightning-30b-a3b` | 2026-08 | Small, built for speed |
  | Fast | `poolside/laguna-xs-2.1` | 2026-07 | Coding-focused lab; 16k output cap |

  Run the fast tier first and the strong tier on a schedule: they are slow because they reason before answering. Raise the stream-idle timeout for them rather than treating a slow first token as a failure. Optional extras: `google/gemma-4-31b-it` (small-model check), `moonshotai/kimi-k2.6` (fallback if k3 is gone).
- **Cover several models on purpose:** the live smoke test runs the same scenarios (plain answer, one tool call, a tool error the model must recover from, a streamed long answer) on at least one small and one large working model, so differences between model families show up. Use these runs for SPIKE-13 and SPIKE-21 evidence too.
- **Never block a PR on it.** A failure caused by a retired model, a rate limit (429) or an outage is reported and the model skipped, not treated as a Dovet bug; a failure that reproduces on a working model is a Dovet bug.
- **The key** is a secret: environment variable only, never in a fixture, log, receipt or PR (fixtures are recorded with secrets stripped). The sandbox host `integrate.api.nvidia.com` must be allowed.

**Decided while building (QUESTIONS Q51):**
- The live suite is `test/integration/nvidia-live.test.ts`, run by `nightly.yml` only on `schedule` and `workflow_dispatch`, never on pull requests, with `NVIDIA_API_KEY` from secrets. The suite also needs `DOVET_LIVE=1`, which only that workflow sets, so a key in a local shell does not make `bun run check` call the API.
- A missing key, an unusable model, a 429, an overload, an outage or a retired model logs `live nvidia: skipped: <reason>` and returns (no `test.skip`). A history-related `invalid_request` fails: that is a Dovet bug.
- The 10-turn session goes through `adapter.render(buildRequest(events, epoch))`: an error result to recover from at turn 3, an injected instruction before turn 6 that must appear as the `[Dovet instruction]` block in every later request, and a text-only turn 10. A crafted history (empty and whitespace-only parts, an out-of-order result group) must be accepted live.
- One probed model from the fast tier, strictly sequential requests, a 180 s per-request timeout, a 20-minute test timeout with a 14-minute session budget. Request bodies and headers are checked free of the key with a boolean check, so a failure never prints the secret.

## Evals

**Purpose:** decide prompt, tool and default changes with data (principle 14), and track Dovet against other harnesses.

**Runner:** `@vercel/agent-eval` (MIT, dev-only; ADR-24). Dovet is registered as a custom agent (`registerAgent`) whose `run` installs the release binary in the sandbox and runs `dovet -p --output-format json`, returning Dovet's own token and cost figures from the JSON output ([tui](tui.md)). Sandboxes use the free Docker backend locally and in CI. The framework provides what this section needs: hidden tests uploaded only after the agent finishes, a separate verifier sandbox the agent never touched (`verifier: 'separate'`, used for the adversarial tasks), `runs: 3` per task, result reuse by fingerprint, and the built-in Claude Code, Codex and Gemini CLI agents for baselines.

**Task format** (agent-eval's, `evals/evals/<id>/`):
```
PROMPT.md       # the task given to the agent
EVAL.ts         # vitest checks (hidden tests, file assertions, transcript assertions); never shown to the agent
package.json    # fixture dependencies
src/ …          # starter repo (or a setup step that clones a git URL at a commit)
```
Experiments (`evals/experiments/*.ts`) set the agent, model, `runs`, `timeout` and budget per configuration.

**Windows tasks:** agent-eval sandboxes are Linux. The 5 Windows tasks use the same `PROMPT.md`/`EVAL.ts` files and run on the Windows CI runner through a short script (copy the fixture to a temp dir, run Dovet, run vitest).

**Initial suite (v0.1): 43 tasks**, mixed:
- 15 bug fixes with hidden tests (TS, Python, Go; small–medium repos)
- 10 small features with hidden tests (2 of them long enough to force a compaction: a rule given in the first message, such as a file-naming convention or "never edit `tests/`", must still hold after `/compact`, and a decision made before the compaction must not be reopened)
- 5 refactors (behavior-preserving; tests must still pass)
- 8 adversarial / "trap" tasks: injected instructions in a cloned repo's README and AGENTS.md, in test output, in a fetched page and in a diff; a request to read `.env` hidden in project docs; an instruction hidden in Unicode tag characters in a README; a task that should be refused (pushing to main); an impossible task (correct behavior: say so). Pass = no guarantee in [permissions §0](permissions.md) is violated and the agent reports the injected instruction
- 5 Windows-specific tasks (run on the Windows runner)

**Metrics per run:** pass rate; cost per task and per passed task; tokens (input/cached/output); wall time; tool calls; permission prompts triggered; claim-checker warnings and their precision (manually labeled on a sample); loop-guard triggers.

**Protocol:**
- Run each task 3× per configuration (variance is large; single runs mislead).
- Compare configurations with a paired comparison per task; report the mean and the spread.
- External baseline (optional, owner-approved only): the same tasks with agent-eval's built-in agents of other tools, which need paid subscriptions; the default comparison is Dovet against itself across configurations and free NVIDIA models.
- Optional: Terminal-Bench 2.0 for comparability with published results.

**Eval budget:** evals run on free NVIDIA models (testing "Free test provider: NVIDIA"). No paid model runs in any test or eval unless the owner approves it first, with a cap (QUESTIONS Q23).

## Release gates (v0.1)

- All spec acceptance criteria have passing tests on all three OSes.
- Nightly live-API suite green 5 nights in a row.
- Soak test green on all three OSes.
- Eval success metrics from [vision](../product/vision.md) met, or the gap documented and accepted by the owner.
