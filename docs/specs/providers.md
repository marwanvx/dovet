## Model layer: the AI SDK [DECISION-30]

Dovet does **not** implement provider wire formats itself. Every model request goes through **Vercel's AI SDK** (`ai` core plus the `@ai-sdk/*` provider packages, Apache-2.0, released together several times a week) [VERIFIED 2026-10-12: `ai` 7.0.137, provider packages 2026-10-08/09]. Those packages are maintained against each provider's API and already handle what this spec used to describe by hand: request and response formats, streaming, tool-call assembly, reasoning replay (Anthropic signatures, OpenAI encrypted reasoning, Gemini thought signatures, Chinese providers' `reasoning_content`), cache-control flags, mid-conversation system messages and per-message effort, provider tools (web search, `apply_patch`, `shell`), and normalized token usage including cached tokens.

**How Dovet calls it:** one generic adapter ([interfaces §3](interfaces.md)) calls `streamText` for **exactly one model step** per request: tools are passed **without `execute` functions** (Dovet's agent loop runs every tool, [agent-loop](agent-loop.md)), `maxRetries: 0` (Dovet's retry policy, §7), `allowSystemInMessages: true` (mid-epoch instructions, [context §4](context.md)), and a custom `fetch` on every provider records the exact request bytes (§6b). Dovet does **not** use the SDK's agent classes (`ToolLoopAgent`): the loop, permissions, epochs, budgets and receipts are Dovet's core.

| Endpoint kind | Package | Covers |
|---|---|---|
| Anthropic Messages | `@ai-sdk/anthropic` | Anthropic API; Anthropic-compatible endpoints of other providers (coding plans) |
| OpenAI Responses | `@ai-sdk/openai` (`openai.responses(...)`) | OpenAI API, incl. Sign in with ChatGPT ([cli-config](cli-config.md)) |
| Open Responses servers | `@ai-sdk/open-responses` | OpenRouter, Ollama (≥ 0.13.3), LM Studio, vLLM, Hugging Face and other [Open Responses](https://www.openresponses.org) servers |
| Gemini | `@ai-sdk/google` (`google.interactions(...)`, the Interactions API) | Gemini API |
| Provider-specific packages | `@ai-sdk/deepseek`, `@ai-sdk/alibaba` (Qwen), `@ai-sdk/moonshotai` (Kimi), `@ai-sdk/zai` (GLM), `@ai-sdk/minimax`, `@ai-sdk/xai`, `@ai-sdk/groq`, `@ai-sdk/mistral`, `@ai-sdk/gateway` (Vercel AI Gateway), … | Each provider's own quirks (reasoning replay, cache usage fields) |
| Any other OpenAI-compatible API | `@ai-sdk/openai-compatible` | Chat Completions fallback: llama.cpp server, older local servers, providers without a package |

**AI SDK helpers Dovet uses instead of its own code** (all from `ai`, [VERIFIED 2026-10-12 against `ai` 7.0.137 type declarations]):
- `wrapLanguageModel` + `extractReasoningMiddleware({ tagName })`: for endpoints whose models put reasoning inline in the text (`<think>…</think>`, common on local servers without a reasoning parser). Enabled by the endpoint quirk `reasoningTags` ([interfaces §2b](interfaces.md)); the reasoning then shows and is stored like any other reasoning block.
- `wrapLanguageModel` + `simulateStreamingMiddleware()`: for endpoints that can't stream (quirk `streaming: false`); the UI gets one chunk per block instead of a broken stream.
- `parsePartialJson`: shows streaming tool arguments in the UI. Display only; tool input is always parsed strictly when complete ([agent-loop](agent-loop.md)).
- `ai/test` (`MockLanguageModelV4`, `simulateReadableStream`): the scripted model for loop, Session-API and soak tests ([testing](testing.md)).

**AI SDK features Dovet deliberately doesn't use:** `toolApproval` / `needsApproval` and `@ai-sdk/policy-opa` (tools have no `execute`, so permission decisions stay in Dovet's effect-based policy engine, [permissions](permissions.md)); `experimental_repairToolCall` (malformed tool input is reported to the model, never silently repaired, [agent-loop](agent-loop.md)); `pruneMessages` (editing history inside an epoch breaks the prefix rule; context shrinks only through compaction, [context](context.md)); the SDK's own retries (`maxRetries: 0`, §7, so every attempt is logged and shown).

**Which package a provider uses** comes from its registry record; for generic records, from the models.dev `npm` field (§ Provider registry). Dovet bundles the official `@ai-sdk/*` provider packages and a short list of vetted community packages in the binary (no installs at runtime); a provider whose package isn't bundled uses `@ai-sdk/openai-compatible` or `@ai-sdk/open-responses` when its API allows.

**What stays Dovet's job** (this spec): which endpoint and package each provider uses, login methods and billing (registry); where cache breakpoints go and their TTL (passed as `providerOptions`); effort defaults and mapping; the replay rule across model switches (§1); refusal handling; the retry and failover policy; cost from the catalog. **Fidelity guard:** the SDK versions are pinned exactly, and every upgrade must pass the golden replay tests, including Anthropic's `prefix_mismatch_behavior: "error"` CI run (AC-PROV-03) and the prefix property test (AC-PROV-02) [SPIKE-44]. If a package lags on something Dovet needs, the fix is a provider option or a small custom provider written against the AI SDK's provider interface (`@ai-sdk/provider`), never a separate code path in the loop.

## Provider registry: one generic approach for every provider

Dovet's core has **no per-company code paths**. Every provider (US labs, Chinese labs such as DeepSeek, Qwen/Alibaba, Kimi/Moonshot, GLM/Z.ai, MiniMax, ByteDance, gateways and local servers) is a **record in a provider registry** (`ai/providers.jsonc`, schema in [interfaces §2b](interfaces.md)), and one generic flow (`/login`, [cli-config](cli-config.md)) plus the one generic adapter over the AI SDK do the rest. A record holds:

| Field | Meaning | Why it's needed |
|---|---|---|
| `endpoints[]` | Each endpoint: `region` (e.g. `global`, `china`), `plan` (`platform` / `coding-plan` / `chatgpt-plan`), `package` (the AI SDK provider package, e.g. `@ai-sdk/anthropic`), `protocol` (the API kind, for conformance tests and diagnostics), `baseUrl`, `models` source | Chinese providers run **separate China and international platforms**, and a key only works on its own platform: DashScope `dashscope.aliyuncs.com` vs `dashscope-intl…`, Moonshot `api.moonshot.cn` vs `.ai`, Zhipu `open.bigmodel.cn` vs `api.z.ai`, MiniMax `api.minimaxi.com` vs `api.minimax.io`. **Coding plans** use their own keys and endpoints, often Anthropic-compatible (Z.ai `/api/anthropic`, MiniMax `/anthropic`) |
| `auth[]` | Methods: `api-key` (env var names, key-format hint such as a prefix), `oauth` (`pkce` / `device` / `paste-code`, only where the provider officially permits third-party tools), `none` (local) | One flow serves keys, official subscription logins and local servers |
| `billing` per endpoint or method | `per-token` (prices from the catalog) or `plan` (subscription or coding plan: tokens shown, no invented dollars) | Coding plans and ChatGPT plans aren't priced per token |
| `models` | `catalog` (models.dev), `endpoint` (the provider's `/models` call), or `static` (listed in the record) | Plan accounts see different models than the catalog lists |
| `search` per endpoint | How WebSearch's `provider` backend searches there: `anthropic-server-tool`, `responses-web-search` (OpenAI; Qwen 3.5+ through Alibaba's Responses API), `gemini-grounding`, or none. Only officially documented mechanisms are listed; providers without one (e.g. Kimi, GLM today) use a search service | WebSearch works on any provider that has search, not only three ([tools §10](tools.md)) |
| `quirks`, `capabilities` overrides | Per-endpoint flags ([interfaces §2b](interfaces.md)) | Compatible endpoints differ in caching, reasoning fields and tool-call details |
| `status` | `tested` (Dovet's conformance suite passes, SPIKE-21) or `community` | The picker shows which ones Dovet has verified |

**Where records come from:**
1. **Curated records** ship in the binary and are covered by fixture and contract tests.
2. **Generic records** are derived automatically from the models.dev provider list. [VERIFIED 2026-10-11: 226 providers, each with `api` (base URL), `env` (key variable names), `npm` (SDK package) and its models.] China and international platforms and **coding plans** are separate entries there (e.g. `moonshotai` / `moonshotai-cn`, `zai` / `zhipuai` / `zai-coding-plan`, `alibaba` / `alibaba-cn` / `alibaba-coding-plan`, `minimax` / `minimax-cn` / `minimax-coding-plan`, `kimi-code-plan-global` / `-cn`, `volcengine` / `volcengine-coding-plan`, `tencent-coding-plan`). The `npm` field **is** the AI SDK provider package Dovet uses (186 of the 226 use `@ai-sdk/openai-compatible`; the rest name a dedicated package). A record whose package Dovet doesn't bundle falls back to `@ai-sdk/openai-compatible` when its API is OpenAI-compatible, else it isn't auto-connectable. Billing is `plan` for entries whose id contains `coding-plan`, `code-plan` or `token-plan`, else `per-token`. Generic entries of one company are grouped under one picker item with a region/plan choice by a small curated alias table (`moonshotai*` → Kimi). Any provider there with an OpenAI- or Anthropic-compatible API is connectable without a Dovet release, labeled `community` until it passes conformance.
3. **User records** go in `providers` in user settings (a custom endpoint, or an override of any field).

**Provider modules (code, only where data isn't enough).** Every provider is a record and goes through the same generic path. When a provider needs behavior a record can't describe (a login flow, request signing, model discovery from a local server, an extra header or body field computed per request, a usage field in an unusual place), it gets a **provider module** `ai/providers/<record-id>.ts` implementing `ProviderModule` ([interfaces §3](interfaces.md)): optional hooks `login`, `listModels`, `prepareRequest` (headers, `providerOptions`), `readUsage`, `classifyError`. The registry looks modules up by record id; the agent loop, transcript and tools never know which provider is in use. Adding or fixing one provider touches only its record and module. Modules are written only when a real provider needs one (e.g. Sign in with ChatGPT, OpenRouter attribution headers, Ollama/LM Studio model discovery).

Curated records win over generic ones; user settings win over both.

**Picking a protocol when a provider offers several:** a curated record names the preferred endpoint per plan, chosen by conformance results. The Anthropic-compatible endpoint is preferred only if it passes the replay and caching tests, since many "compatible" endpoints ignore `cache_control` or thinking signatures. Otherwise Open Responses, then Chat Completions.

**Wrong-region keys:** when validation fails with 401/403, Dovet tries the same key once against the provider's **other regions and plans** (same validation call, nothing else). If one accepts it, Dovet says `This key belongs to <provider> China (open.bigmodel.cn). Use that endpoint?`. Mixed-up regions otherwise look like a bad key.

**Provider presets** (curated records; a provider module only where one is listed above): `anthropic`, `openai`, `google`, `openrouter` (responses), `vercel-ai-gateway` (anthropic-messages for Claude models [SPIKE-23], responses for others), `ollama`, `lmstudio`, `vllm`, `groq`, `deepseek` (chat). For gateways, Dovet **pins routing** (AI Gateway `providerOptions.gateway.only`; OpenRouter `provider.only`) to the provider the user chose and records the provider that actually served each request, so routing never changes silently (principle 1).

**Model lifecycle:**
- **Deprecated model** (catalog `status: deprecated`, or a deprecation header or notice from the provider): a startup and `/model` warning names the retirement date if known and the suggested successor. It still works.
- **Retired or unknown model** (404 `not_found` / "model does not exist"): the request is not retried. The turn ends with `Model <id> is no longer available at <provider>. Pick another with /model.` and the `/model` picker opens (interactive), or exit code 1 with the same text (headless). Switching starts a new epoch as usual. Nothing switches automatically (principle 1).
- **Resuming a session whose model has been retired:** resume opens normally, shows the notice, and asks for a replacement model before the first request.
- **Aliases** ("latest", provider aliases that move) are resolved to a concrete model ID when the session starts; the ID is what's logged and replayed, and a moved alias is noted, never followed silently.

**Model IDs, prices and limits are never hard-coded in logic.** They come from the model catalog (below). Model lineups changed many times in 2026 (e.g. Anthropic Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1; OpenAI GPT-6 Astra / GPT-6.1 Sol / GPT-5.6), and code must not need a release when they change again.

## 1. Normalized message model and replay rule

Types are defined in [interfaces §2](interfaces.md). Each `model.response` stores the step's output in **Dovet's own format**: the assistant `Part`s in order, each with its **replay data** (signatures, encrypted reasoning, item IDs, `phase`, `reasoning_content`) under the provider's own field names, plus the provider, package version and exact model ID (the raw response body is saved only with `--debug`, like request bodies, §6b). The adapter converts the AI SDK's response messages to these parts and back. **Why Dovet's format and not the SDK's:** logs are permanent (resume, rewind, forks), so the log must not depend on any library's internal message shape; replacing the AI SDK for one protocol later changes one adapter and no stored session (ADR-30).

**Lossless round trip (fidelity rule):** for every provider package, the conversion AI SDK messages → stored parts → AI SDK messages reproduces the original messages exactly, and the replayed request bytes match a direct replay. A contract test checks this on every recorded fixture and on every SDK upgrade [SPIKE-44]. Any provider metadata field the adapter doesn't recognize is kept verbatim in `replay.fields`, so new provider fields survive without a Dovet release.

**Replay rule (critical):** when rendering a transcript for protocol *P* and model *M*, an assistant turn is replayed **with its replay data, unchanged,** only if it was produced by the same provider and model *M*. Otherwise it is rendered without replay data: reasoning parts are dropped entirely (with their signatures/encrypted content); text and tool calls are rendered from `text`, `name` and `inputJson`. This makes model switches safe and visible (the switch is a `settings.change` event and the user is told reasoning history won't carry over).

**Exception:** Anthropic itself accepts some cross-model thinking blocks (e.g. Sonnet 5.5 reads Opus 4.8 and Haiku 5.5 blocks) [VERIFIED 2026-10-10]. Dovet does not use this in v0.1; same-model only keeps it simple and predictable.

**Tool call IDs across providers:** IDs are opaque strings stored as received. When replaying a foreign-provider tool call (after a provider switch), the adapter always maps its ID deterministically to `dovet_<sha256(originalId)[0..24]>` (the call and its result get the same mapped ID), a format every provider accepts.

## 2. The adapter (in `ai`)

The normative contract is [interfaces §3](interfaces.md) (`ProviderAdapter`, `RenderInput`, `StreamEvent`, `ProviderErrorInfo`): **one generic implementation over the AI SDK**; per-provider differences are registry data and `providerOptions`. Capabilities per model come from the catalog plus overrides: mid-conversation system messages, reasoning replay, caching profile, parallel tool calls, images, PDFs, forced tool choice, context/output limits, effort levels, server search.

### Effort mapping
Dovet exposes one `effort` setting; adapters map it per protocol. A level the model doesn't support maps to the **nearest lower** supported level, and the effective value is shown in the status bar and `/why` (never silently different).

| Dovet `effort` | Anthropic `output_config.effort` | OpenAI `reasoning.effort` | Gemini `thinkingLevel` | Chat fallback |
|---|---|---|---|---|
| `low` | `low` | `low` | `low` | quirk `effortField` (`reasoning_effort`, or none) |
| `medium` | `medium` | `medium` | `medium` (else `low`) | 〃 |
| `high` | `high` | `high` | `high` | 〃 |
| `xhigh` | `xhigh` | `xhigh` if supported, else `high` | `high` | 〃 |
| `max` | `max` | highest supported | `high` | 〃 |

The supported levels per model come from the catalog (`effortLevels`); OpenAI's set is verified (SPIKE-8), Gemini's is confirmed with SPIKE-19.

**Normalized stop reasons:** `end_turn`, `tool_use`, `max_tokens`, `context_exceeded`, `refusal`, `pause` (server tool loop paused), `stop_sequence`, `other(raw)`. Handling is defined in [specs/agent-loop.md](agent-loop.md).

**Refusals and content filters, normalized for every protocol** (each provider signals them differently, usually inside a successful response, not as an HTTP error):

| Protocol / provider | Signal | Maps to |
|---|---|---|
| anthropic-messages | `stop_reason: "refusal"` + `stop_details.category` | `refusal` with that category |
| openai-responses | an output content part `{type: "refusal", refusal}` | `refusal`, category `model` |
| openai-chat (OpenAI, DeepSeek, Qwen, Kimi, GLM, …) | `finish_reason: "content_filter"` (often with empty content) | `refusal`, category `content_filter` |
| google-interactions | `finishReason` `SAFETY` / `PROHIBITED_CONTENT` / `BLOCKLIST` / `SPII` | `refusal`, category from the reason |
| any | HTTP 400 whose error code is a provider's documented content-policy code (in the registry record) | `refusal`, not a retryable error |

The pre-output retry rule ([agent-loop](agent-loop.md)) applies only where the provider documents false positives and no charge for them (currently Anthropic's unbilled categories). Other providers' filters aren't retried automatically: the user sees the provider and category and decides. A model's own polite refusal in plain text (`finish_reason: stop`) is an ordinary answer.

### Valid tool calls by construction (strict tools)

The best fix for broken tool calls is to make them impossible. Where the endpoint supports it, Dovet declares its tools with **`strict: true`** (the AI SDK's `tool({ strict })`, passed through by the provider packages): the provider then constrains the model's sampling to the tool's JSON Schema, so the call always has a valid tool name, correct types and every required field [VERIFIED 2026-10-12: Anthropic "Strict tool use" docs; `ai` 7.0.137 types; `strict` passed through by `@ai-sdk/anthropic`, `@ai-sdk/openai-compatible`, `@ai-sdk/open-responses`].

- **One schema, every provider.** Each built-in tool has one zod schema. The adapter renders it in the strict form the endpoint needs (`strictTools.optionalStyle`): **`omit`** (Anthropic: optional fields left out of `required`) or **`nullable`** (OpenAI, Gemini: every field in `required`, optional ones typed `X | null`). Tool input normalization treats `null` as "not given" ([tools §0](tools.md)), so both forms produce the same tool input. This makes tool calls equally reliable on every provider that supports strict tools, and keeps tool schemas simple enough for all of them.
- **Which endpoints** (capability `strictTools`, [interfaces §2b](interfaces.md)):
  - **Anthropic:** all current Claude models; at most 20 strict tools, 24 optional parameters and 16 union-typed parameters per request, summed over all strict tools; the first request with a new tool set waits while the grammar compiles (cached 24 h).
  - **OpenAI (Responses):** `strict: true` on function tools; all fields required, optional ones nullable, `additionalProperties: false`; a schema that doesn't meet the rules is rejected with details [VERIFIED 2026-10-12, OpenAI function-calling guide]. Responses silently falls back to non-strict when it can't normalize a schema itself, so Dovet always sends the strict form explicitly.
  - **Gemini:** the `validated` function-calling mode ("model ensures function schema adherence") [VERIFIED 2026-10-12, Gemini function-calling docs]. `@ai-sdk/google` sets it for strict tools on `generateContent` but not yet on `google.interactions` (2026-10-12 source) [SPIKE-46].
  - **Local and Open Responses servers:** recorded per endpoint once verified [SPIKE-46]; until then `null` (not strict).
- **Which tools, within the limits:** tools are marked strict in a fixed order until the next tool would exceed a limit: Edit, Write, Bash/PowerShell, Read, then the rest in tool-list order. The order is part of the epoch's tool definitions, so it never changes mid-epoch (prefix rule, [context](context.md)). MCP tools are never strict (their schemas often use unsupported keywords).
- **Schema rules:** Dovet's built-in tool schemas stay inside the strict subset: `additionalProperties: false` on every object, no `minimum`/`maximum`/`minLength`/`maxLength`, no recursive schemas; such limits are checked by Dovet's own zod validation instead ([tools §0](tools.md)). The JSON Schema generated from a zod schema contains those keywords, so the strict renderer moves them into the field's description ("at least 1") before sending. A unit test sends every built-in schema through each strict endpoint's rules.
- **What strict doesn't fix:** a call cut off by the output limit, and calls that are well-formed but wrong (an `old_string` that isn't in the file). Those still get a precise error and the loop guards ([agent-loop](agent-loop.md)).
- If the provider rejects the strict schemas (a 400 such as "schema too complex"; this can only happen on the first request of an epoch, since the tool definitions don't change inside one), Dovet starts a new epoch whose tool definitions omit `strict` (epoch reason `repair`; nothing was cached yet, so it costs nothing) and keeps strict off for that endpoint and model for the session; the event is logged and `doctor` reports it.

## 3. Anthropic (`@ai-sdk/anthropic`) — first-class in v0.1

All facts below [VERIFIED 2026-10-10/12 against Anthropic's API documentation and the `@ai-sdk/anthropic` docs]. The package produces the wire format; the bullets are Dovet's settings (sent as call options and `providerOptions.anthropic`) and the behavior the contract tests check.

**Request shape**
- `max_tokens`: default = the model's maximum output (128,000 on Opus 5.5 and Sonnet 5.5, as Anthropic recommends for agentic coding; thinking counts toward it), capped by `capabilities`; configurable.
- `thinking: { type: "adaptive", display: "summarized" }` on every adaptive-thinking model. Current models default to `"omitted"` (empty thinking text); `"summarized"` returns readable summaries of the reasoning **and** of the progress updates some models (Fable 5.1, Opus 5.5, Sonnet 5.5) write between tool calls, which the TUI shows as dim lines. (`"updates"` would return the progress updates only and hide the reasoning summaries `/why` needs, so it isn't used.) [VERIFIED 2026-10-12]. Never send `budget_tokens` to models that reject it (Fable 5/5.1, Opus 5.5/5/4.8/4.7, Sonnet 5.5/5, Haiku 5.5). Never send `thinking: {type:"disabled"}` to Opus 5.5 or Sonnet 5.5 (400). A response cut off by `max_tokens` right after a tool step can end with a progress block reading `This part of the response was interrupted before it finished.`; it is shown like any update.
- `inference_geo`: sent only when `providers.anthropic.inferenceGeo` is set (data residency; prices ×1.1, [receipts-budgets](receipts-budgets.md)).
- `output_config: { effort }`: **always sent explicitly** [DECISION-14]. Default = the model's **recommended agentic level** from the catalog (`capabilities.recommendedEffort`; Opus 5.5 and Sonnet 5.5: `medium`, because levels are recalibrated per model and `medium` on Opus 5.5 matches Opus 5 at `high`), else `high`; user-configurable (`low`/`medium`/`high`/`xhigh`/`max`, filtered by model support). `/effort` uses the **per-message effort change** (an effort-only system message, beta `mid-conversation-output-config-2026-07-01`, added by the AI SDK) on models that support it (Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5, Sonnet 5.5, Haiku 5.5 on the Claude API), which keeps the prompt cache; elsewhere it changes the top-level value [VERIFIED 2026-10-12].
- Never send `temperature`/`top_p`/`top_k` to current Claude models (rejected; `capabilities.samplingParams: false`) and never an assistant prefill (400). Other providers follow their model's registry sampling defaults (§ Sampling below).
- `tool_choice`: always `{type:"auto"}`. Never `any`/`tool` [DECISION-14].
- Tools: defined from zod schemas, passed **sorted by name**, strict schemas where allowed, eager input streaming on.

**Caching (explicit)**
- Render order is `tools → system → messages`; any byte change invalidates everything after it.
- One explicit `cache_control: {type:"ephemeral"}` on the **last system block**, plus top-level automatic caching (`cache_control` on the request) for the growing tail. Max 4 breakpoints.
- In long turns with more than ~15 new blocks, add an intermediate breakpoint (20-block lookback window).
- **TTL:** the lifetime is measured **from the start of the request** that wrote or read the entry [VERIFIED 2026-10-11, platform.claude.com prompt caching], so a turn whose model call plus tool run exceeds 5 minutes (a long test suite) loses the 5-minute cache mid-turn. With `cache.ttl: "auto"` (default), the explicit breakpoint on the **last system block** (tools + system, stable for the whole epoch) uses **1 h**, and the automatic tail breakpoint uses **5 m**. The stable prefix survives user pauses and long tool runs; its extra write cost (2× vs 1.25× input, paid once per epoch) is shown in `/cost`. `"5m"` / `"1h"` force one TTL everywhere [SPIKE-33: TTL ordering rules, and whether the measured hit rate justifies `auto`].
- **Keep-alive** (`cache.keepAlive: true`, default **off**, principle 3; shown and counted when on): when the user is idle near the tail's expiry, send the transcript plus a one-character user message with the same thinking/effort and `max_tokens: 1`; the response is discarded and never appended. (`max_tokens: 0` is not documented; community warmers use 1–8 [SPIKE-33].)
- **Never mutate a rendered request.** The body sent is exactly the bytes `render()` produced and hashed (`model.request`); transport middleware may add headers only. (A proxy that rewrites requests, for example by moving mid-conversation system messages into `system`, silently invalidates the cache; Dovet's own transport never does this.)
- **Cache-miss diagnosis:** each `model.request` also stores a **prefix fingerprint**: SHA-256 of the rendered tools, the system blocks and each message. When cache reads fall to 0 (or below 50% of the previous request's prefix) after turn 3, the status bar warns, and `/why --cache` names the **first block that differs** from the previous request. That is a Dovet bug, a provider-side change, or a gateway rewriting the request; routing through a gateway is named as a suspect. Effort or thinking-config changes are expected misses and say so; the `/effort` and `/model` warnings are skipped when the cache has already expired anyway and on models where effort doesn't invalidate the cache (capability `effortInvalidatesCache`).
- **Per-model cache-read prices differ** (0.1× input on most models, 0.05× on Opus/Sonnet 5.5, 0.025× on Fable 5.1 [VERIFIED]); costs use the catalog price, with `pricing-rules.jsonc` filling gaps.
- Tool additions mid-conversation can keep the cache with the `inline-tools-2026-09-15` beta [VERIFIED]: the mechanism for v0.2 deferred MCP tools ([extensibility](extensibility.md)).
- Verification: log `cache_creation_input_tokens` and `cache_read_input_tokens` every turn. Total input = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. A status-bar warning appears if reads drop to 0 after turn 3 (a silent invalidator = a bug).

**Append-only + preserved thinking** [DECISION-3]
- Assistant content is stored with its replay data and replayed unchanged (thinking blocks, signatures, `redacted_thinking`, server-tool blocks, compaction blocks), with **one deterministic replay normalization** applied identically from the first replay on, so prefixes stay stable: empty text blocks are dropped, as are content blocks the API rejects on input (e.g. ones a third-party proxy injected). Without it, a session whose history contains such a block fails every request on resume [SPIKE-34: confirm against `prefix_mismatch_behavior: "error"`]. The repair epoch ([event-log](event-log.md)) remains the last resort for rejections this doesn't cover.
- Mid-epoch instructions: a `{role:"system", content}` message appended after the latest user/tool_result message, on models that support it (Opus 5/5.5/4.8, Fable 5/5.1, Sonnet 5.5, Haiku 5.5; **not** Sonnet 5). Fallback on a 400 `role 'system' is not supported`: a text block after the `tool_result` blocks in the same user message. Earlier copies are never deleted.
- CI runs the Anthropic integration tests [SPIKE-17] with beta `thinking-binding-controls-2026-08-01` and `thinking.block_binding.prefix_mismatch_behavior: "error"` so any history edit fails the build.
- Production sends `prefix_mismatch_behavior: "error"` too: a mismatch can only mean a Dovet bug. On that 400, recover once by stripping thinking blocks and retrying, log an `InvariantViolation`, and tell the user.

**Stop reasons:** `end_turn`, `tool_use`, `max_tokens`, `pause_turn` (server tool loop hit 10 iterations: re-send unchanged to resume, max 5 continuations), `refusal` (check `stop_details.category`; never run that turn's tools), `model_context_window_exceeded`, `stop_sequence`.

**Eager input streaming caveat:** tool input arrives unvalidated. Validate the parsed input with the tool's zod schema. On failure, do not run the tool; return `{"type":"tool_result","tool_use_id":…,"is_error":true,"content":"{\"INVALID_JSON\": \"…\"}"}` (built with `JSON.stringify`). If the SDK throws a JSON parse error before the block completes, re-issue the request (max 2), rethrowing typed API errors.

**Refusal fallback:** the server-side `fallbacks` parameter (beta `server-side-fallback-2026-07-01`, `fallbacks: "default"`) is **off by default** (principle 1). Option `refusal.fallback: "server-default"` enables it. When a fallback answers, the receipt and status line show both models and the refusal category.

**Errors and retries:** errors arrive two ways. Before streaming starts they arrive as an HTTP status. **After streaming starts they arrive as an SSE `event: error`** (e.g. `overloaded_error`) inside a 200 response, with no `message_stop` after it. The adapter maps both to the same `ProviderErrorInfo` kinds; an in-stream error ends the stream, its partial output is discarded, and the retry policy applies. 429 `rate_limit_error` (respect `retry-after`), 500 `api_error`, 529 `overloaded_error` → retry; 400/401/402/403/404/413 → fatal with message. SDK `maxRetries` is set to 0; Dovet's own retry policy applies (section 7) so every attempt is visible and logged.

**Images:** user attachments and Read-tool images go in as base64 `image` blocks. **PDFs:** base64 `document` blocks (v0.1; at most 8 pages per Read at the default token limit, [tools §1](tools.md)). For content reused across many turns, the Files API (`client.files.*`, GA) is a v0.2 optimization.

**Server tools used in v0.1:** web search only (`web_search_20260209`, or `web_search_20250305` on older models/Vertex), and only inside WebSearch's **secondary request** ([tools §10](tools.md), ADR-25), never in the main conversation's tools; `pause_turn` is handled inside that request. Its fees come from `usage.server_tool_use.web_search_requests` [VERIFIED 2026-10-12].
**Not used in v0.1:** server-side compaction (`compact-2026-01-12`), context editing, tool search, web fetch server tool, code execution, memory tool, task budgets, fast mode. Each is a candidate for v0.2 behind evals.

## 4. OpenAI and Open Responses (`@ai-sdk/openai`, `@ai-sdk/open-responses`)

[VERIFIED 2026-10-11/12 against OpenAI docs and the AI SDK provider docs]. Settings below are passed as `providerOptions.openai`; the package handles the item formats.

- Responses API, `stream: true`, `store: false` (stateless; Dovet owns history). In stateless mode reasoning items carry `encrypted_content` **by default**; the old `include: ["reasoning.encrypted_content"]` is accepted for compatibility and sent anyway for older servers.
- **`reasoning.context: "all_turns"`** on every request, so the model uses reasoning from earlier turns (the default may be `current_turn` on newer models) [VERIFIED].
- **Assistant `phase`** (`commentary` for preambles before tool calls, `final_answer` for the finished answer): preserved exactly on replay. OpenAI warns that dropping it makes preambles look like final answers and causes early stopping on GPT-5.4/5.5 [VERIFIED].
- **Replay:** stored parts are converted back to the package's messages, which it turns into input items, keeping item IDs and encrypted reasoning (`include: ['reasoning.encrypted_content']`); `phase` preservation is checked by a contract test [SPIKE-44].
- **Reasoning items:** store the completed item from `response.output_item.done` (encrypted content can be incomplete while in progress) and replay it verbatim in `input` on later requests (same model only).
- **Function calls:** stream via `response.output_item.added` → `response.function_call_arguments.delta` → `.done` → `response.output_item.done`. Results go back as `function_call_output` items with the matching `call_id`.
- **Tools:** the same function tools as every other model ([tools](tools.md)); OpenAI's native `apply_patch` and `shell` tools are not used (one tool set for every model, [prompts](../prompts/README.md)).
- **Mid-conversation instructions:** append an input message with `role: "developer"`.
- **Caching (capability-driven, three caching modes):** always send `prompt_cache_key` = session ID. Then by the model's catalog capability `caching` ([interfaces §2b](interfaces.md)):
  - `openai-automatic` (older models): nothing else.
  - `openai-retention` (GPT-5.5 / 5.5-pro and similar): `prompt_cache_retention: "24h"` (for these models only `24h` is supported).
  - `openai-options` (GPT-5.6 and later): `prompt_cache_options: { mode: "explicit", ttl: "30m" }` plus `prompt_cache_breakpoint: {mode: "explicit"}` on the last block of the stable prefix (max 4 breakpoints written per request; matching considers the latest 80). `prompt_cache_retention` is **deprecated** there and not sent. (`ttl: "30m"` is currently the only value and the default.)
  The capability comes from the catalog/overrides, never from parsing the model name. Fixtures cover all three modes. Read cached tokens from `usage.input_tokens_details.cached_tokens`. Open Responses servers: quirk flag `caching: "none" | "automatic"` disables the cache-hit warning where unsupported.
- **Reasoning effort:** `reasoning: { effort }`, always explicit.
- **Errors:** 429 (rate limit, or insufficient quota: not retryable, detected from the error code), 5xx and capacity errors retryable.

## 5. Google (`@ai-sdk/google`, Interactions API)

[VERIFIED 2026-10-11/12: Gemini API docs and the `@ai-sdk/google` docs (`google.interactions(...)`)]

- Requests use `store: false`. **Stateless full-history replay** (`store: false`) is supported: Dovet sends the whole epoch each time, exactly like the other protocols; implicit caching still works without stored interactions. `previous_interaction_id` (server-side state) is **not** used (Dovet owns history; principle 1).
- Schema is typed **steps** (`user_input`, `thought`, `function_call`, `model_output`, `function_result`) instead of role/parts. Tools: `{type: "function", name, description, parameters}`. Function results: `{type: "function_result", name, call_id, result}`.
- **Thought signatures (critical):** thought/function-call steps carry signatures that must be replayed exactly as received (on Gemini 3+, missing signatures are a 400 even at minimal thinking) [VERIFIED]. Stored in the part's replay data.
- Thinking: `thinkingLevel`, thought summaries (`thinkingSummaries`) shown as reasoning summaries. System instructions and tool declarations are repeated on every request (stateless).
- Usage: `total_input_tokens`, `total_cached_tokens`, `total_output_tokens`, `total_thought_tokens`, `total_tool_use_tokens` [VERIFIED SDK types].
- Mid-conversation instructions: a `user_input` step prefixed `[Harness instruction]` (Interactions has no system-role step; `system_instruction` is per request and part of the frozen header).
- **Fallback:** if a needed model isn't on Interactions, the adapter can target `generateContentStream` (same SDK; `thoughtSignature` on parts, `functionResponse` parts, `automaticFunctionCalling: {disable: true}`). Built only if needed [SPIKE-19].

## 6. Other providers and the Chat Completions fallback

Providers with their own AI SDK package (DeepSeek, Qwen/Alibaba, Kimi/Moonshot, MiniMax, xAI, Groq, Mistral, …) use it; the package handles their reasoning-content replay and cache-usage fields. Anything else OpenAI-compatible uses `@ai-sdk/openai-compatible` (Chat Completions), the lowest-fidelity path. Local runtimes (Ollama, LM Studio, vLLM) use `@ai-sdk/open-responses` by default. The rules below are Dovet's settings for these endpoints.

- Chat Completions with `stream: true`, `stream_options: { include_usage: true }`.
- Tool calls stream as `choices[].delta.tool_calls[]` fragments keyed by `index`; accumulate per index; arguments are parsed only when the stream ends.
- **Sampling parameters are per model, from the vendor's model card** (registry `sampling`, with separate values for thinking and non-thinking modes where the vendor gives them). Open models are tuned for specific values in agentic coding, and server defaults are often wrong for them. **Rule for filling them:** a value enters a curated record only with a link to the vendor's official model card for that exact model, checked when the record is written or updated; models without verified values get no sampling parameters (server defaults). The same rule applies to content-policy error codes (`refusalErrorCodes`). Dovet sends exactly the record's values: none for models whose API rejects sampling (current Claude, OpenAI reasoning models), and the record's values for everyone else. `models.<id>.sampling` overrides them; `/why` shows what was sent.
- **Reasoning replay for chat-protocol reasoning models** (handled by the provider's own AI SDK package where one exists; the registry quirk `reasoningReplay` applies to `@ai-sdk/openai-compatible` endpoints only): some providers require the model's `reasoning_content` to be sent back within a tool-calling loop and dropped between user turns (e.g. Kimi and DeepSeek thinking modes with tools), others reject it in requests. Getting this wrong causes 400s or degraded tool use, so each record states `"in-tool-loop" | "always" | "never"` (values only from the vendor's documentation, as for sampling).
- **Prompt caching for every provider** (registry `caching` and `usage` mapping): most providers cache identical prefixes automatically. DeepSeek, Kimi, Qwen and GLM do (Qwen also accepts explicit cache markers on some endpoints). Dovet's byte-stable, append-only prefix benefits them all without extra work. What differs is **where cached tokens are reported**: DeepSeek `usage.prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`, Kimi `usage.cached_tokens`, Qwen and OpenAI `usage.prompt_tokens_details.cached_tokens`. Each record maps its fields, so costs and the cache gauge are right for every provider; an unmapped provider shows cache stats as "not reported", never 0%.
- Many servers deviate. Per-provider flags in the catalog entry (`Capabilities.tools` / `.parallelTools` and `Quirks`, [interfaces §2b](interfaces.md)): `supportsTools`, `supportsParallelTools`, `supportsStreamUsage`, `reasoningField` (`reasoning_content` | `reasoning_details` | none; matches models.dev `interleaved.field`), `requiresToolCallIdFormat`, `maxImages`, `effortField`, `reasoningTags` (tag name of inline reasoning, e.g. `think`), `streaming` (false → simulated streaming).
- If a model lacks native tool calling (`supportsTools: false`), Dovet refuses agent mode for it with a clear message (no prompt-based tool-call parsing in v0.1).
- Local servers: Ollama (`http://localhost:11434/v1`), LM Studio (`http://localhost:1234/v1`), llama.cpp server, vLLM. No API key needed (a dummy is sent).

### Testing local without a strong machine
1. **Recorded fixtures (primary):** real SSE streams recorded once from Ollama/OpenRouter and replayed by the fixture server in CI ([testing](testing.md)). Covers parsing, tool-call accumulation and quirks.
2. **Tiny CPU model (smoke test):** `qwen3:0.6b` via Ollama (~1 GB RAM, tool calling supported per community reports [SPIKE-11]). Expect unreliable tool-call JSON; it tests the *pipe*, not quality.
3. **Hosted OpenAI-compatible endpoints:** OpenRouter or Groq exercise the identical code path cheaply.

## 6b. Transport (all providers)

- **HTTP stack:** the AI SDK uses Bun's `fetch`. Corporate proxies via `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` (honored natively by Bun) or `network.proxy`; extra CA certificates via `NODE_EXTRA_CA_CERTS` or `network.caCertFile` [VERIFIED 2026-10-11, Bun docs].
- **Exact request capture (glass box):** every provider instance gets a custom `fetch` wrapper that records the **exact serialized request body bytes**, request ID and response headers (the SDK's `include.requestBody` is used in tests to cross-check). The body's SHA-256 goes into `model.request`; with `--debug` (or `/why --request`) the redacted request body is saved, and with `--debug` the raw response body too. This is also how the prefix-property CI test observes real bytes.
- **Timeouts:** connect 30 s; stream idle 180 s; no total timeout ([agent-loop](agent-loop.md)). AI SDK retries disabled (`maxRetries: 0`); Dovet's policy below applies.
- **Offline:** if the provider is unreachable at startup, the session still opens (history, `/resume`, `/receipt` work); the first request fails with a clear network error and the retry policy applies.

## 7. Retry and failover policy (all providers)

| Situation | Behavior |
|---|---|
| Retryable error (429 with retry-after, 5xx, 529, capacity, network reset, idle/first-byte timeout, a **damaged stream**: unparseable SSE data or a missing final event) | Exponential backoff with full jitter: base 2 s, factor 2, cap 60 s; honor `retry-after`, with a **minimum of 1 s** even when it says 0. **One budget of 6 attempts per model call**, shared by every cause including stream drops. The status line shows "Retrying (3/6) in 8s — overloaded (529), request id …". Each attempt is a `model.error` event. A damaged stream is never shown raw (no "JSON Parse error" or "undefined" in answers). |
| Stream dies after partial output | If **at least one text or tool-call block completed**, those blocks are kept exactly as for an interrupt ([agent-loop](agent-loop.md)): complete tool calls get `Not run: the connection dropped before your response finished. Re-issue the call if it is still needed.` The next request continues the turn with the instruction part `Your previous response was cut off by a connection error after the blocks above. Continue from there.` Otherwise, including thinking-only progress, the partial output is discarded and the request retried. Both paths use the attempt budget. |
| Error body that isn't JSON (a proxy's HTML 429/502 page) | Classified by status; the message shows the status, the proxy's name if known and the page's `<title>`, never raw markup. |
| Server answers a streaming request without streaming (a gateway returning one JSON or `text/plain` body) | Parsed as a complete, non-streamed response if it is a valid response object; otherwise classified by status as a damaged stream and retried within the budget |
| 429 insufficient quota / billing | Fatal; tell the user which account and the provider's message. |
| All retries exhausted | Turn ends with error. If `failover` is configured, offer "Switch to <fallback model> for this session?" **The user must confirm**, unless `failover.auto: true`, in which case the switch still happens visibly (banner + receipt + `settings.change` event). |

**First response limits:** the first request after start or a model switch uses the server's limits (`models.retrieve`, waited for at most 1.5 s, else the catalog), not built-in defaults.

**Never silent** (principle 1): no automatic provider or model switch without a visible event.

## 8. Model catalog & pricing

- **Source:** `https://models.dev/api.json` (an open model database) [VERIFIED 2026-10-10, README]. Fields used: `cost.input`, `cost.output`, `cost.cache_read`, `cost.cache_write`, `cost.reasoning` (USD per 1M tokens), `limit.context`, `limit.input`, `limit.output`, `tool_call`, `reasoning`, `attachment`, `modalities.input`, `interleaved`, `status`.
- A snapshot is **bundled** in each release (works offline). At startup, if the cached copy is older than 24 h, refresh in the background (one HTTP GET, no auth). On failure, keep the old copy and show nothing unless prices are > 30 days old (then warn).
- **Overrides:** `models` config section can override any field (e.g. a negotiated price, a local model's context size).
- **Live capability checks:** for Anthropic, the Models API (`GET /v1/models/{id}`) gives `max_input_tokens`, `max_tokens` and `capabilities` [VERIFIED]; Dovet calls it once per model per day and prefers it over the catalog for limits.
- **Context-size tiers come from models.dev** [VERIFIED 2026-10-12]: `cost.tiers[]` (each `{input, output, cache_read, cache_write, tier: {type: "context", size}}`; e.g. GPT-6 above 272K, Haiku 5.5 above 100K) and `cost.context_over_200k`. `cache_write` is the 5-minute write price. The small hand-maintained `ai/pricing-rules.jsonc` covers only what models.dev lacks: Anthropic 1-hour cache writes (2× input), data-residency multipliers, and server-tool fees, checked in tests against known examples. A missing price shows `≈` or `?`.

## 9. One tool set and one prompt for every model

Every model, from every provider, gets the same system prompt, the same tools (Read, Write, Edit, Bash or PowerShell by detected shell, Grep, Glob, WebFetch, WebSearch, AskUserQuestion, EnterPlanMode, ExitPlanMode, TodoWrite) and the same tool descriptions ([prompts](../prompts/README.md), [tools](tools.md)). What differs per model is data only: effort levels, thinking display, sampling values, strict-tool support, caching mode and limits, from the catalog and registry. Provider-native tools (Anthropic's `text_editor`/`bash`, OpenAI's `apply_patch`/`shell`) are not used in the main conversation.

A per-model variant (a different tool shape or extra prompt text for one model family) is added only when the eval suite shows a measurable gain for that family that the shared set can't reach, and then by an ADR [SPIKE-13].

## Acceptance criteria

- [ ] **AC-PROV-01** Golden tests: for each protocol, a recorded multi-turn session (text, parallel tools, reasoning, an error result) renders byte-identical requests on replay.
- [ ] **AC-PROV-02** Prefix property test: for each protocol, request N's serialized body (minus cache markers) is a strict prefix of request N+1's within an epoch.
- [ ] **AC-PROV-03** Anthropic CI integration test with `prefix_mismatch_behavior: "error"` passes a 10-turn tool-using session, including an injected mid-epoch instruction.
- [ ] **AC-PROV-04** Gemini integration test (Interactions API, `store: false`): a 3-turn function-calling session succeeds (proves thought-signature replay).
- [ ] **AC-PROV-05** OpenAI integration test: reasoning items and `phase` replayed over a 5-turn tool-using session with the shared tool set.
- [ ] **AC-PROV-06** Ollama fixture tests: Open Responses stream (function call items) and Chat Completions stream (tool-call fragments across 3 chunks) both reassemble into valid JSON.
- [ ] **AC-PROV-07** Gateway presets: requests carry the pinned routing option and the serving provider is recorded in `model.response`.
- [ ] **AC-PROV-08** Switching model mid-session drops foreign reasoning and the next request succeeds on each protocol pair.
- [ ] **AC-PROV-09** Retry: a mocked 529 followed by success yields one visible retry status, two `model.request`/`model.error` events, and a correct final result.
- [ ] **AC-PROV-10** Cost for a recorded Anthropic turn with cache reads and writes matches a hand-computed value to the cent.
- [ ] **AC-PROV-11** An in-stream `event: error` (`overloaded_error`) after partial text is classified retryable, the partial output is discarded, and the retry succeeds (fixture).
- [ ] **AC-PROV-12** Cache diagnosis: a fixture where request 5 changes one earlier message byte makes `/why --cache` name that message; an effort change is reported as an expected miss.
- [ ] **AC-PROV-13** With `cache.ttl: auto`, the system breakpoint carries `ttl: "1h"` and the tail `5m`; the request body sent equals the rendered body byte-for-byte (hash check in the transport).
- [ ] **AC-PROV-14** Retry budget: a call that fails by stream drops, then 529s, then a damaged stream sends at most 6 requests in total; `Retry-After: 0` still waits ≥ 1 s; a proxy HTML 502 page is reported by status and title.
- [ ] **AC-PROV-15** A stream that drops after one complete text block and one complete tool call keeps both; the tool call gets the not-run result; the next request carries the continue instruction and succeeds; a thinking-only drop is retried from scratch.
- [ ] **AC-PROV-16** A 404 "model not found" ends the turn without retries and opens the `/model` picker; a catalog-deprecated model shows a warning with its successor; a resumed session on a retired model asks for a replacement before its first request.
- [ ] **AC-PROV-17** On Anthropic, the request's tool definitions carry `strict: true` for Edit, Write, Bash and Read and stay within the strict limits (20 tools, 24 optional, 16 union parameters); every built-in schema passes the strict-subset unit test; a fake 400 "schema too complex" on an epoch's first request is resent without `strict` and logged.
- [ ] **AC-PROV-18** For every bundled provider package and every recorded fixture: AI SDK response messages → `StoredResponse` → AI SDK messages is deep-equal to the original, and the re-rendered request bytes equal a direct replay; the event log contains no AI SDK message objects (schema check), and an unknown provider metadata field survives the round trip.
