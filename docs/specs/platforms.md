Windows, macOS and Linux are all first-class (principle 12). This page is the single place that lists every OS difference. All OS-specific code lives in the `platform` package behind one interface.

## Windows specifics

**Shell resolution** (`platform.resolveShell()`):
1. `shell.windows` config: `git-bash` | `powershell` | `auto` (default).
2. `auto`: Git Bash from `DOVET_GIT_BASH_PATH`, then `git --exec-path` → `..\..\..\bin\bash.exe`, then `%ProgramFiles%\Git\bin\bash.exe`, `%LocalAppData%\Programs\Git\bin\bash.exe`. **Never** `C:\Windows\System32\bash.exe` (that is WSL's launcher).
3. Else `pwsh.exe` on PATH; else `powershell.exe`.

**Git for Windows missing (owner decision, 2026-10-12):** the install script and the first-run wizard ask once: `Git for Windows isn't installed. Dovet works best with its Git Bash. Install it now with winget (Microsoft's package manager)? [Yes / No]`. Yes runs `winget install --id Git.Git -e --source winget` and re-resolves the shell; No (or no winget) uses PowerShell and doesn't ask again (`dovet doctor` still mentions it). Nothing is installed without that answer, and headless runs never install.
4. The chosen shell and version are shown in the system prompt environment block and the status bar (e.g. `PowerShell 7.5`), and the matching tool (Bash or PowerShell) is the one exposed.

Both paths are needed: many Windows developers have Git Bash, and many don't. **Git Bash first** is an owner decision (2026-10-12): models write bash best and the permission analyzer is strongest for bash. The Windows eval still measures both shells.

**Paths in Git Bash:** the model may write `/c/Users/...` style paths. Dovet's file tools accept `C:\...`, `C:/...` and `/c/...` (converted via `cygpath -w` semantics implemented in `platform`, no subprocess; Dovet never calls `cygpath`, which is missing from some Git for Windows installs). MSYS argument conversion stays **on** (`MSYS_NO_PATHCONV` not set): turning it off breaks calling Windows programs with `/c/…` paths. The Git Bash variant of the Bash description tells the model to prefix a single command with `MSYS_NO_PATHCONV=1` when an argument starting with `/` or `//` must not be converted.

**Executable resolution (security):** every program Dovet spawns itself (`git`, `rg`, `bash`, `pwsh`, `pdftotext`, clipboard tools) is resolved **once, by Dovet**, to an absolute path by searching `PATH` while **skipping `.`, empty entries and any directory inside the project**. The result is cached per session; lookups are async and a missing tool is cached as missing. Windows `CreateProcess` searches the *current directory* before `PATH`, so a repository shipping `git.exe` in its root would otherwise run as soon as Dovet opened it. Child shells get `NoDefaultCurrentDirectoryInExePath=1`, so `cmd.exe` doesn't do this either. Microsoft Store / winget `pwsh` is an App Execution Alias (a zero-byte reparse point); Dovet resolves it to the real executable or launches it through its alias correctly [SPIKE-14].

**Network and device paths (security):** file tools and working directories refuse UNC paths (`\\server\share`), `\\?\UNC\…`, NT `\??\` paths and `\\.\` device paths after canonicalization. Touching a UNC path makes Windows send the user's NTLM credentials to that server (a credential leak). Mapped drive letters work. The same applies to `/net/<host>` automounts on macOS/Linux for added directories.

**Windows filesystem quirks:** directory creation tolerates existing directories, the read-only attribute and OneDrive placeholders. A session cwd that is deleted or unmounted mid-session doesn't crash Dovet: commands report it, and the cwd resets to the project root.

**Dovet's own git calls** (status for the environment block, snapshots, diffs) always run with `GIT_OPTIONAL_LOCKS=0` / `--no-optional-locks`, so they never touch `.git/index`, and with `GIT_TRACE*`/`GIT_TRACE2*` unset, because trace output mixed into git's stdout would be misread as repository state. In addition:
- **Plumbing only, never filters:** the environment block uses `rev-parse`/`symbolic-ref` (branch, HEAD), never `git status` or a work-tree `git diff`. Those run clean filters, including a nested repository's. Snapshots are filter-free by design ([checkpoints](checkpoints.md)).
- **No lazy fetches:** `GIT_NO_LAZY_FETCH=1`, so a partial clone (Scalar/GVFS, `--filter=blob:none`) never downloads blobs because Dovet looked at it. A missing object is "not restorable", not a network fetch.
- **No credential prompts:** `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, `-c credential.helper=`, so Git Credential Manager popups never appear. (With optional locks off, read-only git calls never refresh the index, which would otherwise trigger file-watcher loops in editors.)

**Path length:** temp and helper paths Dovet creates are kept short (`<data>\tmp\…` with 8-char ids), and long project paths are passed with the `\\?\` prefix where Win32 APIs need it. PowerShell fails on script paths over 260 characters.

**Encoding:** console code page issues: force UTF-8 for spawned PowerShell (see [tools](tools.md)); for Git Bash set `LANG=C.UTF-8` if unset; decode output as UTF-8 with replacement.

**Terminal:** Windows Terminal recommended; legacy conhost works in basic mode. Capabilities are detected by query, never by name ([tui Terminal I/O robustness](tui.md)). VT processing must be enabled (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`) [SPIKE-4: does Bun/pi-tui do this automatically?].

**File locking:** antivirus and editors lock files; rename retries with backoff, then an in-place write (Write §2.7 in [tools](tools.md)).

**Long paths:** paths > 260 chars require the `LongPathsEnabled` registry setting; Dovet detects ENAMETOOLONG and reports the setting in the error and in `dovet doctor`.

**Signals:** no SIGINT to child process trees; use tree-kill. Ctrl+C in the TUI is handled by the TUI's raw-mode input, not the console's signal.

**Shell selection (QUESTIONS Q39):** `Platform.resolveShell(setting?: { windows, gitBashPath })` returns `{ kind: "bash" | "git-bash" | "powershell", path, edition?, note? }`. A forced `git-bash` without Git Bash falls back to PowerShell with a `note`; the result is cached per tool instance.

## macOS specifics

- Seatbelt via `sandbox-exec` (deprecated by Apple but still functional and widely used by coding agents; monitored as a risk).
- Gatekeeper: binaries downloaded by browsers get quarantined; the install script uses `curl`, and Homebrew (v0.2) installs too, neither of which sets the quarantine attribute. Apple notarization needs a paid developer account and waits until the project has income.
- Case-insensitive APFS: path comparisons use the volume's case sensitivity [SPIKE-10].

## Linux specifics

- Sandbox dependencies: `bwrap` ≥ 0.4 (warn < 0.5), `socat`. Ubuntu 24.04+ restricts unprivileged user namespaces via AppArmor; `dovet doctor` detects it (`/proc/sys/kernel/apparmor_restrict_unprivileged_userns`) and prints the documented fix.
- Inside containers: nested sandbox only with `sandbox.enableWeakerNestedSandbox: true`.
- WSL2: behaves as Linux; files on `/mnt/c` are slow, and doctor warns if the workspace is there.
- Keychain: Secret Service may be absent on servers → credentials in a 0600 file, or env-var keys ([cli-config "Secrets"](cli-config.md)).

## CI matrix

Every PR runs unit + integration tests on `ubuntu-latest`, `macos-latest` (arm64) and `windows-latest`. Nightly adds: Ubuntu 24.04 with AppArmor restriction on, macOS x64, Windows with only PowerShell 5.1 (no Git Bash, no pwsh), Alpine (musl build).

## Acceptance criteria

- [ ] **AC-PLAT-01** `platform.resolveShell()` tests per OS with injected filesystem states (Git Bash present/absent, pwsh present/absent).
- [ ] **AC-PLAT-02** Process-tree kill test passes on all three OSes.
- [ ] **AC-PLAT-03** Git-Bash-style path `/c/Users/x/a.txt` resolves to `C:\Users\x\a.txt` on Windows.
- [ ] **AC-PLAT-04** Unicode output (`echo "héllo 你好"`) round-trips correctly through every shell on every OS.
- [ ] **AC-PLAT-05** Windows: a project containing `git.exe` and `rg.exe` in its root never has them executed by Dovet (planted binaries write a marker file; the test asserts it's absent); `Read \\\\127.0.0.1\\c$\\x` and `\\??\\C:\\x` are refused.
- [ ] **AC-PLAT-06** Windows: Python printing non-ASCII under PowerShell and Git Bash succeeds; `echo x 2>nul` in Git Bash creates no `nul` file; deleting the session cwd mid-session yields a clear error and a reset to the project root.
