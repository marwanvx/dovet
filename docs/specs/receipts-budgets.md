## Part A — Receipts

A **receipt** is generated by code from the event log at the end of every user turn. It is never written by the model.

### Receipt contents

```
┌ Receipt · turn 7 · 2m 41s · claude-opus-5-5 (effort medium)
│ Files   M src/auth/session.ts   +42 −9
│         A src/auth/token.ts     +88
│         M test/auth.test.ts     +31 −2
│         M package-lock.json     (by shell: npm install)
│ Commands  ✓ npm install (12.4s)   ✗ npm test (exit 1, 8.1s)   ✓ npm test (exit 0, 7.9s)
│ Network   registry.npmjs.org (sandbox)  ·  WebFetch: docs.example.com
│ Approvals 2 asked (2 allowed) · 5 auto-allowed by rules
│ Sandbox   on · 1 violation (write to ~/.cache/x blocked)
│ Tokens    in 182.4k (cache read 151.0k, write 9.2k) · out 6.1k
│ Cost      $0.31 this turn · $2.14 session · budget $5.00 (43%)
│ Checkpoint  c7 — /rewind c7 to undo these file changes
│ Checks    ⚠ Response says "updated README.md" but README.md was not changed in this session.
└
```

| Section | Source events |
|---|---|
| Files | `file.change` (A/M/D/R; changes made by shell commands are attributed to the command; `~` marks changes that are not restorable, e.g. non-git workspaces) |
| Commands | `tool.result` of shell tools: command (truncated to 60 chars), exit code, duration |
| Network | sandbox proxy logs (domains reached) + WebFetch and WebSearch calls (search fees included in Cost) |
| Plan | link to the approved plan file, if the turn followed ExitPlanMode |
| Approvals | `permission.decision` counts by source |
| Sandbox | state + violations |
| Tokens / Cost | `model.response` usage across the turn (and compaction calls) |
| Checkpoint | `checkpoint` event |
| Checks | claim checker (below) |

Display: collapsed to one line in the transcript by default (`✓ 3 files · 3 commands · $0.31 · ⚠ 1 check`), expandable. `/receipt [turn]` shows the full receipt. Headless JSON output includes the receipt object.

### Claim checker

The goal is to catch the most common lie: "I did X" when X didn't happen. It is **deterministic and conservative**: a warning means "not verified by the log", never "the model lied".

**Check 1 — file claims.** In the final assistant text of the turn (text parts after the last tool call):
1. Extract path-like tokens: any token that matches an existing file path relative to the workspace (or cwd), or a path that appears in this turn's `file.change` events, or a backticked token containing `/` or `.` with a file extension.
2. For each extracted path, look for a **change verb** within the same sentence: `updated|modified|changed|edited|fixed|added|created|wrote|removed|deleted|renamed|refactored|implemented` (English in v0.1; the verb list is a versioned file).
3. If a path has a change verb but **no** `file.change` event for it in this turn (including changes by shell commands): if it **was** changed in an earlier turn of this session, that's a recap and no warning is shown; otherwise → warning `Response says "<verb> <path>" but <path> was not changed in this session.`
4. Negations (`didn't`, `did not`, `not yet`, `no changes to`, `without changing`) within 4 tokens before the verb suppress the check.

**Check 2 — test claims.** If the final text matches `/(tests?|specs?|suite|build|lint|typecheck)\b.{0,40}\b(pass(es|ed|ing)?|succeed(s|ed)?|green|all good|working)/i`:
- Find shell commands in this turn matching the test-command patterns (`test`, `jest`, `vitest`, `pytest`, `cargo test`, `go test`, `mvn test`, `gradle test`, `npm/pnpm/yarn/bun (run )?test`, `make test`, `tsc`, `eslint`, `biome`, `ruff`, … versioned file).
- None ran → warning `Response claims tests pass, but no test command ran this turn.`
- The **last** matching command exited non-zero → warning `Response claims tests pass, but the last test run (<cmd>) exited with code N.`

**Check 3 — command claims.** "I ran X" / "I've run X" where X is a backticked command with no matching shell call this turn → warning.

The checker's **precision and recall** are measured on labeled eval transcripts (target: false-positive rate < 5%; recall reported, not gated) and both numbers are published in the docs with its limits. It only checks claims about files, tests and commands against the log; it cannot verify semantic claims ("fixed the bug"), and a passing test command does not prove correctness. The receipt says "not verified by the log", never "false".

## Part B — Budgets

### Cost computation

Per `model.response`, from raw usage fields ([providers](providers.md)) and catalog prices:

| Provider | Formula (per 1M tokens) |
|---|---|
| Anthropic | `input_tokens × in + cache_creation(5m) × in × 1.25 + cache_creation(1h) × in × 2 + cache_read × cache_read_price + output_tokens × out` (uses `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` when present) |
| OpenAI | `(input_tokens − cached_tokens) × in + cached_tokens × cache_read + output_tokens × out` (output includes reasoning tokens) + long-context tier rules |
| Google (Interactions) | `(total_input_tokens − total_cached_tokens) × in + total_cached_tokens × cache_read + (total_output_tokens + total_thought_tokens) × out` (+ tool-use tokens if billed separately [SPIKE-19]) |
| **Plan-billed** endpoints (ChatGPT sign-in, coding plans; [providers "Provider registry"](providers.md)) | No dollar cost: the meter and receipts show tokens and `billed to plan allowance` (`cost.turnUsd: null`, `approximate: false`); dollar budgets don't apply, and `budget.tokens` limits the session instead |
| Server tool fees | `count × price per call` for provider-side tools (web search), counts from usage (`server_tool_use.web_search_requests` on Anthropic), prices from `pricing-rules.jsonc` |
| OpenAI-compatible (DeepSeek, Qwen, Kimi, GLM, gateways, …) | `(input − cached) × in + cached × cache_read + output × out`, where `cached` is read from the record's `usageFields.cachedInput` (DeepSeek `prompt_cache_hit_tokens`, Kimi `cached_tokens`, Qwen `prompt_tokens_details.cached_tokens`; [providers](providers.md)) and reasoning tokens count as output; prices are the provider's own (often region-specific: China vs international platforms differ); local models default to $0 |

**Rules that apply to every formula:**
- **Prices are looked up by provider + model,** never by model alone. The same model costs differently on Anthropic, Bedrock, Vertex, OpenRouter or a gateway. models.dev prices are per provider.
- **Every model call is costed and attributed,** with its purpose in the receipt: main requests, compaction summaries, WebSearch's secondary request, keep-alive pings, title generation, repair requests.
- **Per-attempt usage:** when a response carries `usage.iterations` (Anthropic server-side fallback, server-tool iterations), each iteration is priced at **its own model's** rates, and the receipt names every model that ran. The top-level `model` field is the model that answered.
- **Refusals:**
  - a refusal before any output is billed only for the categories Anthropic lists as billed (currently `bio`, `frontier_llm`, `reasoning_extraction`); otherwise it costs $0;
  - a mid-stream refusal bills input plus the output already streamed.
  - The receipt shows the refusal category either way.
- **Data residency:** with `providers.anthropic.inferenceGeo: "us"` (sent as `inference_geo`), every price category on Claude 4.6 and later models is multiplied by **1.1**. Regional or multi-region cloud endpoints (Bedrock, Vertex) carry their own **+10%**, from the provider record.
- **Haiku 5.5 long-context tier:** a request whose prompt (input + cache reads + cache writes) exceeds 100,000 tokens is priced entirely at the higher rates; similar tiers live in `pricing-rules.jsonc`.
- **Web search** (provider backend): $10 per 1,000 searches on Anthropic plus the tokens of the results; searches that error aren't billed. Search-service backends: counted, priced only if `websearch.pricePerSearch` is set.

Prices with tiers come from `pricing-rules.jsonc` ([providers §8](providers.md)). Any cost computed with a missing or unknown price shows `≈` or `?` — never a fake `$0.00`.

### Budget scopes

| Scope | Config key | Default |
|---|---|---|
| Per turn | `budget.turn` | none |
| Per session | `budget.session` | none (costs are always shown live; `/budget` or the setting adds a limit) |
| Per day (all sessions, local time) | `budget.daily` | none |
| Tokens per session (plan-billed endpoints, where dollars don't apply) | `budget.tokens` | none |
| CLI override | `--budget 2.50` (session) | — |

### Behavior

1. **Pre-flight estimate:** before each request, estimate its cost = (estimated uncached input × input price) + (estimated cache reads × cache price) + (expected output: the session's median output per request, min 2,000 tokens) × output price. Input token estimate: last response's actual total input + new content's chars/3.5 (conservative). No count-tokens API call per request (latency); exception: before compaction decisions on Anthropic, `messages.countTokens` may be used (free, but adds latency) [v0.2].
2. **80% of any budget** → a status-bar warning and a `budget.event`. No interruption.
3. **Next request would exceed a budget** (spent + estimate > limit) → pause **before** sending: "Session budget $5.00 would be exceeded (spent $4.71, next request ≈ $0.40). [Extend +$5] [Extend to…] [Stop]". In headless mode: stop with exit code 4 and a JSON reason.
4. A single request can still overshoot (estimates aren't exact); the overshoot is shown in the receipt. Hard guarantee: **no new request starts** once spent ≥ limit.
5. **Daily budget across concurrent sessions:** reading sidecars is racy (two sessions could both pass pre-flight). Instead, a per-day **reservation ledger** `<data>/budget/<YYYY-MM-DD>.ledger` (append-only lines) guarded by a short-held exclusive lock file (`open("wx")` + 2 s stale timeout):
   - before each request: lock → sum committed + outstanding reservations → if `sum + estimate > daily limit`, pause (no request) → else append `reserve <session> <requestId> <estimate>` → unlock;
   - after the response (or on error/cancel): append `commit <requestId> <actual>` or `release <requestId>`;
   - reservations older than 30 min without commit/release (crashed session) are treated as committed at their estimate until the owning session's lock heartbeat proves it alive or it is cleaned by GC.
   This makes the daily cap **hard across all Dovet sessions on one machine** (not across machines). A single request can still exceed its estimate; the overshoot is bounded by that request and shown in the receipt.

### Live meter (status bar)

`$0.31 turn · $2.14 session · 43% of $5` plus a context-window gauge (`ctx 34%`), always visible. `/cost` shows a breakdown by model, by purpose (main, compaction, search, …), by turn, cached vs uncached, and a **cache line**: hit ratio, the number of misses with their likely cause (TTL expired while idle, effort or model change, a changed block named by `/why --cache`), tokens re-cached, and whether the cache is warm or cold now.

## Acceptance criteria

- [ ] **AC-RCPT-01** Receipt file list equals `file.change` events of the turn (property test over random sessions).
- [ ] **AC-RCPT-02** Claim checker: fixtures for each check, including negations, give exactly the expected warnings.
- [ ] **AC-RCPT-03** A budget of $0.10 stops a scripted session before the request that would exceed it.
- [ ] **AC-RCPT-04** Two sessions racing at 95% of the daily budget: at most one request is dispatched when both estimates together exceed the remainder.
- [ ] **AC-RCPT-05** A crashed session's outstanding reservation is counted until reconciled.
- [ ] **AC-RCPT-06** Unknown pricing shows `?` rather than `$0.00`.
- [ ] **AC-RCPT-07** Cost of recorded sessions for each provider matches hand-computed values.
- [ ] **AC-RCPT-08** A recorded Anthropic response with a `fallback_message` iteration is costed per iteration at each model's price, and the receipt lists both models; a pre-output `cyber` refusal costs $0, while a `bio` one and a mid-stream refusal are billed as specified.
- [ ] **AC-RCPT-09** With `inferenceGeo: "us"`, every price category of a Claude 4.6+ request is ×1.1; the same model via a Bedrock regional endpoint uses that provider's prices +10%; a Haiku 5.5 request with a 120k-token prompt is priced at the long-context rates for all of its tokens.
- [ ] **AC-RCPT-10** Compaction, WebSearch secondary requests and title generation appear in `/cost` under their purposes and are counted toward budgets; a final message recapping a file changed in an earlier turn raises no claim warning.
