## 1. Epochs

A session is a sequence of **epochs**. Each epoch has a **frozen header**, fixed when the epoch starts:

| Header field | Source |
|---|---|
| Provider, model | Session settings |
| System prompt (rendered) | Template + environment block + instruction files (below) |
| Tool definitions | The shared tool set (with the detected shell's tool), rendered and sorted by name |
| Thinking config | e.g. adaptive + display mode (changing it invalidates the cache) |

Request parameters outside `system`/`tools`/`messages` (effort, `max_tokens`, betas, `tool_choice`) are **not** part of the frozen header. Changing them doesn't invalidate reasoning blocks on Anthropic models [VERIFIED 2026-10-10: preserved-thinking rules list `output_config` incl. effort as safe], though an effort change does force a one-time rewrite of the messages cache.

Within an epoch, the request is **append-only** [DECISION-3]. A new epoch starts only at: session start, compaction, or a change that can't be appended (model/provider switch, tool set change, thinking-config change; see table §5). Every epoch change is an event and is shown in the transcript as a divider: `── new context: <reason> ──`.

## 2. System prompt

**Template files** (versioned, part of the glass-box hashes): [prompts/system.md](../prompts/system.md), one for every model (ADR-31), embedded in the binary. Content guidelines:
- Base prompt under ~2,500 tokens (current models need less instruction, and prescriptive prompts written for older models reduce quality on new ones [VERIFIED 2026-10-10, Anthropic migration guidance]).
- **Covers** (every base prompt):
  - acting on requests vs answering questions; investigating before claims; finishing the whole task (no announced-but-undone next steps; compaction awareness);
  - scope (no unrequested additions; report unrelated issues); real solutions (no hard-coding or weakening tests); verification with a real check;
  - tool use (dedicated tools, parallel independent calls, task list, scratch-file cleanup);
  - reversibility (ask before hard-to-reverse or visible actions; no `--no-verify`); never reverting the user's changes; git rules; permission denials (don't retry or route around); sandbox;
  - untrusted content, forged authority, `<pasted_content>`, mid-task user messages, hidden characters, secrets;
  - instruction-file scope and precedence;
  - progress updates, final recap, reviews (findings first), style.

  Based on the model vendors' current prompting guides (Anthropic's per-model guides, OpenAI's GPT-6 guide; verified 2026-10-11, listed in [research log §Prompts](../background/feature-research.md)).
- **No** dates, times, user names or random values inside the template.

**Assembly (layers):** base prompt → session-state sections (permission mode, sandbox state, headless) → conditional sections (WebSearch available, git attribution) → `## Environment` → `## Project instructions`. Each layer, its files and the writing rules are in [prompts/README.md](../prompts/README.md). All layers are fixed at epoch start; changes during an epoch arrive as mid-epoch instructions using the **same** texts (§4).

**Rendered system prompt** = assembled layers + `## Environment` block + `## Project instructions` block:

```
## Environment
- OS: <Windows 11 | macOS 15.x | Ubuntu 24.04 …>  Shell tool: <Bash (bash 5.2) | Bash (bash 3.2, macOS) | PowerShell 7.5 | Git Bash>
- Workspace root: <absolute path>
- Git repository: <yes (branch at session start: main) | no>
- Date at session start: <YYYY-MM-DD>
- Model: <id> via <provider>
```

All of these are fixed at epoch start, so the system prompt is byte-stable for the whole epoch (cache-friendly). The date is the **session start date**; if a session crosses midnight, nothing changes (the next epoch picks up the new date).

**Git commits and pull requests:** the system prompt tells the model to commit only when asked, to follow the project's commit conventions (AGENTS.md/CLAUDE.md, recent `git log` style), and to **add no attribution by default**. Commits are the user's. `git.attribution: "trailer"` adds `Co-authored-by: <model name> via Dovet <noreply@…>` to commit messages the agent writes. A project instruction that asks for or forbids attribution wins over the setting. The receipt always records which commits the agent made, so attribution isn't needed for honesty.

## 3. Instruction files (AGENTS.md, CLAUDE.md, rules)

File names, locations, import syntax and rule frontmatter are compatible with Claude Code's documented memory files [VERIFIED 2026-10-11, code.claude.com/docs/en/memory], so existing CLAUDE.md setups work unchanged; AGENTS.md is treated as an equal.

**Which files (setting `instructions.files`):**
| Value | Loads |
|---|---|
| `both` **(default)** | In each directory: `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, then `AGENTS.md`, `.claude/AGENTS.md`. A file already loaded through an import or symlink is not loaded twice |
| `agents-md-or-claude-md` | AGENTS.md files only, unless a CLAUDE.md exists |
| `claude-md` / `agents-md` | Only that family |

The default loads both families (deduplicated) because Dovet serves every model vendor; repos written for one tool keep working.

**Trust:** instruction files load whether or not the folder is trusted. They are content, like a README, and are treated as untrusted input by the threat model ([permissions §0](permissions.md)). Trust governs configuration that grants capability (settings, hooks, MCP servers), not instructions.

**Loaded exactly once:** every instruction file and import is identified by its **canonical identity** (resolved path, case-folded on case-insensitive volumes, plus device and inode). A file is in the context at most once per epoch, whichever way it was reached: root walk, `.claude/` vs `.dovet/` spelling, import, symlink, lazy load, an `--add-dir` directory inside the working directory, a nested worktree. (Typical duplicate paths: re-attaching after resume or compaction, nested files injected repeatedly, `--add-dir` overlap, nested worktrees, drive-letter case.) The loaded set is rebuilt from `instructions.loaded` events on resume; it is reset only by a new epoch, whose system prompt re-renders the launch set.

**Exclusions and additional directories:** `instructions.exclude` (gitignore-style patterns, matched against both the path and its symlink target) skips files, e.g. another team's rules in a monorepo. Instruction files inside `--add-dir` directories outside the project load only with `instructions.fromAdditionalDirectories: true` (default false).

**Policy applies to instruction files too:** loading obeys `Read` deny rules and `blockReadsOutsideWorkingDirectories`, judged on the **canonical** path (otherwise a project `AGENTS.md` symlinked to a file outside the project would load). A rule or `.claude`/`.dovet` directory that is a symlink to outside the project counts as an **external import** and needs the same one-time approval. Network paths (UNC, macOS `/Network`, `/.vol`) are never read.

**Discovery and order:**
1. User level: `<config>/AGENTS.md`, `<config>/rules/**/*.md` (no `paths`), and, when `instructions.readClaudeUserFiles: true` (default true), `~/.claude/CLAUDE.md` and `~/.claude/rules/`.
2. **Every directory from the filesystem root down to the session's primary working directory**, in that order (closer to the cwd = later = read last). Within a directory, the order in the table above.
3. Project rules: `.dovet/rules/**/*.md` and `.claude/rules/**/*.md` **without** `paths` frontmatter are loaded at launch with the same priority as the directory's main file.
4. **Lazy loads** (appended as mid-epoch instructions, §4, the first time each is triggered):
   - a subdirectory's instruction files (below the cwd), when the agent reads, writes, creates or edits a file in that subdirectory (including recognized shell views, [tools §5.9](tools.md)), or when the user `@`-mentions a file in it;
   - **path-scoped rules**: rule files whose YAML frontmatter has `paths: ["src/api/**/*.ts", …]` load when the agent works with a matching file. `paths` is the only frontmatter key read; invalid YAML → loaded as an unscoped rule, with a warning. A file matches if its requested **or** canonical path matches. Brace expansion in `paths` is budget-bounded (at most 1,000 expanded patterns per file, else a warning and the file loads unscoped); unbounded expansion of many `{a,b}` groups can exhaust memory at startup.

**Imports:** an import is `@` followed by a path, at the start of a line or after whitespace, **outside** inline code spans and fenced code blocks; the path ends at whitespace (consecutive `@~/a @~/b` work). Only text files are imported; binary targets are skipped with a warning. It inlines that file; relative paths resolve against the importing file; absolute and `~/` allowed; **max depth 4 hops**; cycles reported and broken. **External imports** (resolving outside the working directories) in project files need a one-time approval per project (a dialog listing them at session start); declined → skipped with a note.

**Processing:** block-level HTML comments (`<!-- … -->`) are stripped (not inside code blocks). Files over 4 MiB are skipped with a warning. A file over 200 lines, or a combined total (all files and imports together) over 1,000 lines, shows a warning at startup and in `/status` (adherence drops with length). The thresholds scale with the model's context window relative to 200K, capped at 4×. **No silent truncation.**

**Visibility:** `/rules` lists every instruction file found, loaded or **not loaded with the reason** (excluded, denied by a rule, outside the working directories, external import declined, too large). A transcript line notes a nested file that exists but wasn't loaded.

**Rendered block** (in the system prompt, at epoch start):
```
## Project instructions
These come from instruction files in this project and the user's config. Follow them. Later files are more specific and take precedence.

### <path relative to the workspace, or ~/…>
<content>
```

**Changes during a session:** before each user turn, re-stat loaded files (hash only if mtime changed). A changed file is appended as a mid-epoch instruction `Instructions updated (<path>):\n<new content>`. The system prompt is not edited.

**After compaction:** the new epoch re-renders the system prompt from the **current** files on disk (so the root files survive compaction verbatim and fresh). Lazily loaded subdirectory files and path-scoped rules reload on demand again.

**"Rules that stick":** instructions are in the system prompt, never summarized. Rules that can be checked mechanically belong in permission rules (enforced). `/rules` lists both, with the source of each.

**Auto memory [v0.2]** (an explicit error instead of silent truncation when `MEMORY.md` exceeds its read limit; last-modified timestamps in frontmatter are computed when written and never re-rendered per request; frontmatter values must not be cut at an inline `#`): a per-project memory directory `<data>/projects/<id>/memory/` with a `MEMORY.md` index (first 200 lines / 25 KB loaded at session start) and topic files the agent maintains with its normal file tools (no memory tool, no extra model calls). Off by default until evals show it helps; `memory.auto: true` enables it.

**Decided while building (QUESTIONS Q74):** `dovet -p` loads these files into a new session's system prompt and logs an `instructions.loaded` event. It asks nothing, so an external import is skipped for that run with a warning and no stored decision. Before every model request it re-stats the launch files; if one changed it runs discovery again (same Read-deny, size, import and hidden-character checks) and appends the changed file as `instructions-updated`; a resumed session appends the changes before the new user message. A file with hidden characters taints the session. A launch file that drops out mid-turn is recorded in `dropped` on the next `instructions.loaded` event and still watched, so restoring it with the same text announces it again, in the turn and on resume. A path discovery can't read (a locked or looping rules folder, a looping additional directory) is reported as not loadable; a reload that fails for any other reason changes nothing: the earlier launch files stay in force and a warning says why.

**Decided while building (QUESTIONS Q30):**
- An `@path` token is replaced by the imported file's text (comments stripped, its own imports expanded); a skipped import (missing, already loaded, a cycle, too deep, declined) leaves the token as written.
- One part per file; `<dir>` in a lazy part is that file's display path (`Instructions for pkg/AGENTS.md (loaded because you worked with files there)`), the same for a rule.
- `blockReadsOutsideWorkingDirectories` and the external-import approval apply to files reached from inside the working directories (project files, their imports, symlinked project files and rule folders), not to user-level files or the folders above the project. Read deny rules apply to every file.
- `instructions.exclude`: a pattern without a slash matches a file name at any depth; with a slash it matches the path relative to the primary working directory; a leading slash anchors it there and is also tried against the absolute path; a folder match covers its contents; requested and canonical paths are both tried.
- Per directory: if any CLAUDE.md-family file exists, that family loads; otherwise its AGENTS.md files.
- External-import decisions: `<data>/projects/<projectId>/external-imports.json`, one per canonical path. The session-start dialog lists every undecided one together; one first met during a lazy load is asked on its own; a damaged file means asking again.
- A rule's base directory is the folder that holds its `.claude`/`.dovet` folder; for user-level rules, the primary working directory.
- An `--add-dir` inside the project is a working directory, so its files load at launch, deduplicated; outside the project, `instructions.fromAdditionalDirectories` decides and `/rules` lists the skipped files.
- The brace-expansion limit counts the patterns `{a,b}` groups would produce (a product over groups, a sum over alternatives), totaled over the file, without expanding anything.
- Resume: the epoch keeps its stored system prompt; a launch file whose content (or an import's) changed is sent as `instructions-updated`; a new launch file as a `lazy-instructions` part; files attached lazily in the resumed epoch aren't attached again.
- Files are deduplicated by canonical path and by exact `dev:ino` file identity, read as bigint: 64-bit Windows file IDs lose their low bits as doubles (follow-up F1).

**Decided while building (QUESTIONS Q29):** a launch instruction file deleted mid-epoch is announced once as `Instructions updated (<path>):\n(the file was deleted)` and stops being watched until the next epoch.

## 4. Mid-epoch instructions (append-only injection)

Used for: instruction file changes, mode and sandbox changes, budget warnings shown to the model (optional, off by default), the interrupt note, subdirectory instruction files, and the other fixed texts in [prompts/instructions.md](../prompts/instructions.md).

Delivery per protocol ([providers](providers.md)):
| Protocol | Form |
|---|---|
| anthropic-messages (supported models) | `{role:"system", content:"…"}` appended after the latest user/tool_result message |
| anthropic-messages (others) | text block appended after the `tool_result` blocks in the same user message (or in the next user message) |
| openai-responses | input message `role:"developer"` |
| google-interactions / openai-chat | text part in the next user message, prefixed `[Dovet instruction]` |

**Reserved markers can't be forged:** Dovet's own markers (`[Dovet instruction]`, the `▸ dovet:` label and any `<dovet-…>` tag) are escaped wherever they appear in content Dovet didn't author: instruction files, tool results, fetched pages, hook output (v0.2). Invisible characters (zero-width, bidi overrides) in instruction files and tool results are shown visibly in the UI. Text can't impersonate the harness.

Injected instructions are **never removed** later (removal = history edit). Every injection is a `system.injected` event and is visible in the transcript UI as a dim `▸ dovet:` line. Nothing the model sees is hidden from the user.

**Decided while building (QUESTIONS Q29):**
- Reserved markers in instruction files and tool results stay readable but can't match: `[Dovet instruction]` gets full-width brackets (`［Dovet instruction］`), `▸ dovet:` becomes `▹ dovet:`, `<dovet-` becomes `‹dovet-`. Matching ignores case, extra spaces and invisible characters (zero-width, bidi).
- Delivery is decided once, by the adapter's `instructionDelivery`: a developer message on openai-responses; a text block marked `[Dovet instruction] ` on chat and interactions.
- `epoch.start` data: `epoch, reason, provider, model, systemText, toolsJson, thinking, promptVersion`. `PROMPT_VERSION` hashes every `.md` file in `docs/prompts/` except `README.md`, by name and content.

## 5. What forces a new epoch

| Change | Same epoch? |
|---|---|
| Instruction file edited | Yes (mid-epoch instruction) |
| Permission mode change | Yes (mid-epoch instruction) |
| Effort change | Yes. Applies from the next request. On models with per-message effort (`capabilities.perMessageEffort`, beta), an effort-only system message is appended, with no cache reset; elsewhere the top-level `effort` changes, which costs one messages-cache rewrite (the UI shows the estimated cost first) ([providers §3](providers.md), SPIKE-40). |
| Model or provider switch | **New epoch.** The user chooses: carry over a summary (as compaction), or keep the full history (re-sent to the new model with foreign reasoning dropped per the replay rule in [providers](providers.md); full cache rewrite cost shown first). |
| Thinking config change (e.g. display mode) | New epoch (same choice as a model switch) |
| Provider rejects the replayed history (non-retryable, history-related) | Offer a **repair epoch**: same model, normalized transcript re-rendered without opaque reasoning or empty/unpaired items ([event-log Resume](event-log.md)) |
| MCP tools added (v0.2) | Yes, via deferred loading / `tool_addition` where supported; otherwise new epoch |

## 6. Compaction [DECISION-3]

**Partial compaction ("Summarize up to here", from `/rewind`, [checkpoints](checkpoints.md)):** the same summary request, covering only turns before *k*; the new epoch's history is the summary followed by turns ≥ *k* carried as in a model switch (opaque reasoning dropped).

**Shape: simple compaction plus the user's own words.** This is Anthropic's recommended client-side form, extended by keeping the user's messages verbatim. The new epoch starts with:
1. the frozen header (re-rendered: current environment block, including the **current** git branch, not the session-start one);
2. one user message holding:
   - **"Your earlier messages (verbatim)":** every user message of the compacted epoch, oldest first, word for word. If together they exceed `min(32,000 tokens, 10% of the context window)`, the oldest are truncated from the front with a marker, never reworded;
   - **the summary** (model-written, below);
   - **Dovet facts** (code-written, below);
3. the pending user message, if any.

No earlier assistant turns and no earlier thinking blocks are carried over. Keep-tail and background compaction are **not** used (they break preserved thinking). Keeping the user's words mechanically means a constraint can't be lost or paraphrased by a summary ("rules that stick").

**Token estimate used for triggers and the context gauge** (if the last response reported no usage or zero tokens, the whole transcript is estimated from characters instead): `last response's total input tokens (uncached + cache read + cache write) + its output tokens + (chars of text appended since) / 3.5 + images appended since × per-image estimate` (Anthropic: `⌈w/28⌉ × ⌈h/28⌉` visual tokens of the image as sent, after Dovet's resize [VERIFIED 2026-10-11, platform.claude.com vision]; others: catalog `imageTokens` or 1,600 per image). Exact numbers come from the next response's usage; the estimate is deliberately conservative.

**Triggers:**
- **Auto:** before a request, if the estimated input tokens > `compaction.threshold` × the model's **usable input window** (its context window minus the request's `max_tokens` output reserve). Default threshold **0.9**, so each model uses nearly all the context it supports. The window comes from the server's limits for the actual model ([providers §7](providers.md)), never an assumed size (a wrong window makes compaction far too early or too late). `compaction.maxTokens` (default: none) optionally caps it in absolute tokens for cost control; `/context` shows the threshold and what a full-context request costs, since every request re-reads the whole context (principle 3).
- **Manual:** `/compact [focus instructions]`.
- **Forced:** stop reason `context_exceeded`.
- **Never** in the middle of a tool round (an assistant turn with unanswered tool calls). If the threshold is crossed mid-round, compaction waits until the round's results are appended and runs before the next request.

**Procedure:**
1. The summary request is a **fork**: it is sent as a separate request whose prefix is the current epoch's exact transcript plus the compaction prompt, but it is **never appended** to the epoch itself (so `/compact undo` returns to an intact, still-cached epoch). Request a summary from the **same model with the same frozen header** (reuses the prompt cache [VERIFIED: forks must reuse the parent's exact prefix]), by appending a final user message with the compaction prompt ([prompts/compact.md](../prompts/compact.md)). Tools stay declared; the prompt says not to call tools. If the model calls a tool anyway, answer every call with an error result and ask again once; if it still doesn't comply, fall back to a mechanical summary (below).
2. The compaction prompt ([prompts/compact.md](../prompts/compact.md)) asks for sections: **User's requests and constraints**, **What happened** (problems and how they were handled; approaches tried or set aside), **Current state** (exactly what is finished and checked vs in progress, including the task list), and **Next steps**. "Finished vs in progress" must be explicit; a vague summary makes the model redo or retract finished work after compaction. The summary must not phrase anything as a new request.
3. **Dovet facts appended by code, never by the model:**
   - files changed (from `file.change` events);
   - the last result of each distinct test/build command;
   - the **last 5 tool actions with their outcomes** (so the model knows exactly what it last did);
   - the current task list;
   - mode, taint state and session-scoped permission grants;
   - the plan file path, and the plan text itself while in plan mode or implementing an approved plan ([tools §11](tools.md));
   - working directories.
   Inserting model text never goes through string-replacement APIs that interpret `$` sequences.
3b. **When the summary request itself wouldn't fit** (the usual case for a forced `context_exceeded` compaction): the fork can't reuse the full transcript. Dovet builds a reduced copy for the summary request only, in this order, until it fits in `window − 25,000` tokens:
   1. replace images and documents with `[image: <name>]` placeholders;
   2. cut tool results to their first and last 1,000 characters;
   3. drop the oldest turns, keeping the first user message.

   This loses the cache for that request, which is acceptable once; without it, a session that overflowed could never compact and would be stuck.
4. **If the summary request fails** (twice, with its own retry budget: e.g. overload, refusal, a machine that slept mid-request): retry once on `failover.model` if configured; else the **mechanical fallback**: the verbatim user messages plus the Dovet facts, with no model summary, and a notice saying so.
5. Persist a `compaction` event (summary, retained user messages, Dovet facts, tokens before/after, cost); start the new epoch; show a divider with a "view summary" toggle. The TUI keeps all earlier messages in scrollback, and `/context` updates immediately.

**Provider-native compaction** (Anthropic `compact-2026-01-12`, OpenAI Responses compaction): **not used in v0.1.** OpenAI's compaction output is encrypted, so neither the user nor Dovet can see what the model kept, which conflicts with principle 1. A later opt-in (v0.3 candidate, `compaction.mode: "provider"`) would label it as opaque in the UI and receipts.

**Undo:** `/compact undo` (only before the next request is sent) restores the previous epoch (the log still has everything; nothing was deleted).

## 7. Caching checklist (enforced by tests)

- [ ] **AC-CTX-01** Tools sorted by name; JSON Schema generated deterministically (stable key order).
- [ ] **AC-CTX-02** No timestamps/IDs/random values in system prompt or tools.
- [ ] **AC-CTX-03** Anthropic: one explicit breakpoint on the last system block + automatic caching for the tail; intermediate breakpoint when a turn adds > 15 blocks.
- [ ] **AC-CTX-04** Cache-read ratio monitored per request; drop to zero after turn 3 → status-bar warning + `InvariantViolation` log entry.
- [ ] **AC-CTX-05** Integration test: 5-turn session, turns 2–5 each have `cache_read_input_tokens > 0` (Anthropic) / `cached_tokens > 0` (OpenAI, given a long-enough prefix).

## 8. `/why` (glass-box view)

`/why` shows, for the last request: model and params, the epoch number and why it started, the system prompt (rendered, scrollable), tool names with the prompt version, instruction files with hashes, every mid-epoch instruction, cache read/write tokens, and taint state. `/why --request` dumps the exact request body to a file (secrets redacted). Nothing the model received is unavailable to the user.
