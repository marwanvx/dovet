## Modules (one package, enforced boundaries)

**One Bun package** (`src/<module>/`), not a multi-package workspace. A solo developer gains nothing from per-package builds, versioning and tsconfig references, and AI agents navigate one tree more reliably. Boundaries are still enforced: `dependency-cruiser` fails CI on any edge not allowed in the table below. Only `evals/` is a separate package (dev-only). If a module later needs publishing (e.g. the ACP server or a reusable `ai` layer), it can be extracted then.

| Module | Responsibility | May depend on |
|---|---|---|
| `schema` | Zod schemas and inferred types: events, normalized messages, config, tool I/O | (none) |
| `platform` | OS abstraction: directories, shell detection, process spawn/kill trees, path canonicalization, terminal capability detection | `schema` |
| `store` | Event log writer/reader, content-addressed blob store, session metadata sidecars, config loading and merging, secrets (`Bun.secrets`, `just-secrets` fallback), **snapshot service** (git-tree / blob checkpoints, [checkpoints](checkpoints.md)) | `schema`, `platform` |
| `policy` | Permission rules (parse/evaluate), shell command parsing (tree-sitter), path policy, sandbox wrapper (sandbox-runtime), taint state, secret redaction | `schema`, `platform`, `store` |
| `tools` | Built-in tool implementations, tool registry, output limiting and offloading, read-state tracking | `schema`, `platform`, `store`, `policy` |
| `ai` | The model layer: one adapter over the AI SDK and its provider packages (ADR-30), provider registry, model catalog, pricing, retry policy | `schema`, `platform`, `store` |
| `agent` | Session lifecycle, turn loop, transcript builder, compaction, receipts, budgets, loop detection; decides **when** to checkpoint and rewind (the snapshot mechanics live in `store`); applies tool `SessionEffect`s | all of the above |
| `tui` | Vendored pi-tui (`tui/vendor/pi-tui`) and the application UI | `schema`, `platform` (clipboard, terminal detection, notifications, `rg --files` for `@` completion), `agent` (only its public `session-api` entry: `Session`, `Runtime`, event types) |
| `cli` | Entry point, argument parsing, headless output formats, `doctor` | everything |
| `evals` | Eval suite on `@vercel/agent-eval` with a Dovet agent definition (dev-only, not shipped) | `cli` as a subprocess only |
| `mcp` (v0.2) | MCP client; wraps server tools as `ToolDefinition`s | `schema`, `platform`, `store`, `policy`, `tools` (types + registry) |
| `hooks` (v0.2) | Runs hook commands (sandboxed); returns decisions/context | `schema`, `platform`, `policy` |
| `lsp` (v0.2) | Language-server lifecycle; diagnostics post-processor | `schema`, `platform` |

The v0.2 rows are listed now so v0.1 code leaves room for them: `agent` wires them in; nothing below `agent` imports them.

**Dependency direction is enforced in CI** by `dependency-cruiser` (dev-only) with one rule per forbidden edge in the table above, plus `no-circular`. Any violation fails the build.

**Conventions:**
- **Prompts have one home:** `docs/prompts/` is both the spec and the source; the build embeds the files from there (Bun text imports). There are no copies under `src/`.
- **Each module's public surface is its `index.ts`**; other modules import only from it (`agent`'s is `session-api.ts`, re-exported by its `index.ts`). Enforced by `dependency-cruiser`.
- **File names** are kebab-case; one main export per file; no barrel files except each module's `index.ts`.
- **Unit tests sit next to the code** (`edit.ts` → `edit.test.ts`), so agents find them; cross-module and platform tests live in `test/`. Every test that covers a criterion is tagged `// spec: AC-xx-yy` (testing).
- **Package scripts:** `check` (type check, Biome, dependency-cruiser, tests, spec-coverage, docs check), `test`, `build` (compiled binary for the current OS), `release` (all targets, CI only), `record <scenario>` (testing), `gen:schemas`, `docs:boxes`, `docs:check`, `next` (prints the next task and the spec text it needs, [build loop](../workflow/build-loop.md)).
- **No contributor license agreement:** contributions are accepted under the MIT license (inbound = outbound), by pull request; a PR must name its task and acceptance criteria (template).

## Core design: the agent is a UI-agnostic event stream

- `agent` exposes `Session` (exact contract: [interfaces §6](interfaces.md)): `submit`, `sendQueuedNow`, `interrupt`, `answerPermission`, `answerQuestion`, `answerPlan`, `command`, `close`. It emits an async stream of `AgentEvent`s.
- The TUI, headless mode and (in v0.2) the ACP server are all **consumers** of the same stream. None of them contain agent logic.
- `AgentEvent`s are a superset of persisted events: they include transient UI events (`stream.delta`, `status`) that are **not** written to the log.
- **Worker-ready boundary:** every command and every `AgentEvent` is a plain, structured-clone-safe object (no functions, class instances or streams). v0.1 runs the agent in the main thread. If input latency measurements fail (target: keypress-to-echo p99 < 16 ms while streaming and running tools), the agent core moves into a Bun `Worker` without changing either side's code. CPU-heavy work (tree-sitter parsing, large diffs, JSON parsing of huge responses) is the risk being guarded against.

## State ownership

- **Session state** (mode, cwd, taint, working dirs, budgets, epoch, queue) is owned by `agent` alone. Tools receive a read-only snapshot and return `SessionEffect`s ([interfaces §4](interfaces.md)); the agent applies them in emitted order and logs each (`settings.change` / `taint.change`). Policy reads state from `PolicyContext`, never from its own module state.
- **Process state** (config, catalog, secrets, blob store) is owned by `Runtime`; created once by `cli` ([interfaces §9](interfaces.md)).
- **Capabilities flow down by injection, never by import:** tools that need the user (AskUserQuestion, ExitPlanMode) or a model (WebSearch) get them through `ToolContext`; (v0.2) the `Task` tool gets a `spawnChild` capability the same way. This keeps `tools → agent` imports impossible.

## Data flow of one turn

1. User input → `agent` appends `user.message` to the event log.
2. Budget pre-check and compaction check ([receipts-budgets](receipts-budgets.md), [context](context.md)).
3. The **transcript builder** renders the current epoch's events into the provider's request format (deterministic, append-only).
4. `ai` streams the response; deltas go to the UI as transient events; the adapter converts the result into Dovet's own stored parts with provider replay data, persisted as `model.response` (views are derived).
5. For each tool call: validate → policy check (may emit a `permission.request` and wait) → execute (parallel-safe tools concurrently) → persist `tool.result` → file changes persisted as `file.change` with blob refs.
6. Repeat from step 2 until the model ends its turn, then build and persist the **receipt**.

## Process model

- One process per interactive session. No daemon in v0.1.
- Tool executions that run external programs (Bash, ripgrep) are **child processes** in their own process group (POSIX) or killed as a tree with `taskkill /T /F` (Windows). See [specs/platforms.md](platforms.md).
- MCP stdio servers (v0.2) are child processes, sandboxed where possible.
- CPU-heavy parsing (tree-sitter) runs in-process; it is fast enough (sub-millisecond per command). Revisit only if profiling says so.

## Concurrency model

- Single-threaded event loop. One turn runs at a time per session.
- Within a turn, tools marked `parallelSafe` (Read, Grep, Glob, WebFetch, WebSearch; the column in [tools §0](tools.md)) run concurrently up to a limit of 8. Mutating tools (Edit, Write, Bash) run **sequentially, in the order the model emitted them**, after all parallel-safe calls that came before them in the list.
- Every async operation takes an `AbortSignal` that chains from the session's turn controller, so `interrupt()` cancels everything.

## Error model

| Error class | Where | Handling |
|---|---|---|
| `ToolError` | tool execution | Returned to the model as `tool_result` with `is_error: true` and an actionable message. Never crashes the turn. |
| `PolicyDenied` | policy | Returned to the model as an `is_error` result: "Permission denied by user/rule X. Do not retry the same action." |
| `ProviderError` (retryable) | ai | Retried by the retry policy ([providers](providers.md)); surfaced as a status line during retries. |
| `ProviderError` (fatal) | ai | Turn ends; error shown to the user with the provider's request ID; event logged. |
| `InvariantViolation` | anywhere | A bug. Logged with full context; the session stays alive if possible; the user sees "internal error" plus the log path. |
| Config/schema errors | startup | Exit with a message pointing to the exact file, line and field. |

## Distribution

**An install directory, not a single file.** Verified constraints:
- `bun build --compile` embeds files under an internal `/$bunfs/` path. JS can read them, but the OS **cannot execute** a binary from there, so `rg` would have to be extracted at runtime (fragile: `noexec` temp dirs, antivirus, races).
- `@anthropic-ai/sandbox-runtime` locates its helpers (`apply-seccomp`, `srt-win.exe`, Java proxy agent) relative to its own files, or accepts explicit paths. Its own docs warn that helper binaries must sit **outside** any sandbox write grant.

Layout (identical on all OSes):
```
dovet/                 (e.g. ~/.local/share/dovet/versions/<v>/ or %LOCALAPPDATA%\dovet\versions\<v>\)
  dovet(.exe)          compiled Bun executable (JS + WASM grammars + templates + pricing snapshot embedded)
  libexec/
    rg(.exe)           ripgrep for this platform
    srt/               sandbox-runtime helpers for this OS and CPU, flat: apply-seccomp (Linux), srt-win.exe (Windows), srt-proxy-agent.jar
  THIRD_PARTY_NOTICES  license texts and NOTICE files of every bundled package and binary (generated by the release build:
                       npm packages from the build's metafile, the Bun runtime, sandbox-runtime, ripgrep, vendored code)
```
A `dovet` launcher/symlink on PATH points to the current version; `dovet update` installs a new version directory and switches the pointer atomically (old version kept for rollback).

**Release authenticity (v0.1):** a SHA-256 checksum fetched from the same place as the binary detects corruption, not tampering. So every release has two independent controls:
1. **Ed25519 signature:** the release workflow signs `SHA256SUMS` with an offline-held Ed25519 key (key in a GitHub environment requiring manual approval); the public key is **embedded in the Dovet binary and the install scripts**. `dovet update` (WebCrypto Ed25519, available in Bun) and the install scripts (OpenSSL 3 or their own code; cli-config "Install, PATH and uninstall") verify the signature before trusting any checksum. A key rotation ships the new key in a release signed by the old one. Formats: `SHA256SUMS` lines are `<sha256 hex>  <file name>`; `SHA256SUMS.sig` is the raw 64-byte Ed25519 signature of its exact bytes; the private key is base64 PKCS#8, the embedded public keys raw 32-byte base64 (a list, so a rotation can trust old and new). The signing step refuses a key whose public half isn't embedded.
2. **GitHub artifact attestations** (build provenance, `actions/attest-build-provenance`) for every archive, verifiable by users with `gh attestation verify <file> --repo <owner>/dovet --source-ref refs/tags/v<version>`; documented on the install page. `--source-ref` matters: pull requests from the repository's own branches (not forks or Dependabot) that touch the release files build an unpublished test release (throwaway signing key) with real attestations of their own ref, so the pipeline is proven before it is used. The test build also embeds that throwaway public key (and no other) and a loopback update URL in its binaries, so CI can install the built archives with the install scripts and run `dovet update` and `--rollback` on them; release builds from a `v*` tag contain neither, and nothing in the shipped binary reads an environment variable or flag to change which keys or URL `dovet update` trusts.
Third-party GitHub Actions are pinned to full commit SHAs. **OS code signing:** no paid certificates until the project has income (owner decision). Windows binaries are signed through **SignPath Foundation's** free program for open-source projects once accepted (requires the automated, repository-built release pipeline above); macOS is installed via `curl`/Homebrew, which avoids Gatekeeper quarantine.

**Compile flags (security-critical):** `--no-compile-autoload-dotenv` and `--no-compile-autoload-bunfig` (or `compile: {autoloadDotenv: false, autoloadBunfig: false}`). Compiled Bun executables **load `.env` and `bunfig.toml` from the current directory by default** [VERIFIED 2026-10-11, Bun docs]; without these flags Dovet would load every project's `.env` secrets into its own environment and pass them to child processes. A CI test runs the binary in a directory with a planted `.env` and asserts nothing was loaded.

- Targets (all available in Bun 1.4 [VERIFIED]): `bun-linux-x64`, `bun-linux-arm64`, `bun-linux-x64-musl`, `bun-linux-arm64-musl`, `bun-darwin-arm64`, `bun-darwin-x64`, `bun-windows-x64`, `bun-windows-arm64`.
- **Alpine on arm64 has no bundled `rg`** (owner decision, 2026-10-12): ripgrep publishes no Linux arm64 musl build, so the `linux-arm64-musl` archive has no `libexec/rg`. Dovet uses an `rg` on `PATH` there and says so (tools "Grep"); `dovet doctor` and the install script tell the user to run `apk add ripgrep`. The other seven archives all bundle ripgrep.
- Embedded in the executable: tree-sitter WASM grammars (`tree-sitter-bash.wasm`, `tree-sitter-powershell.wasm`, shipped inside those npm packages) and `web-tree-sitter.wasm`, the models.dev pricing snapshot, and the prompt files from `docs/prompts/`.
- Install methods (v0.1): GitHub Releases archives plus an install script (`curl | sh` on POSIX, `irm | iex` on Windows). Package managers (npm, Homebrew, winget, Scoop) come in v0.2.
- Self-update: `dovet update` downloads the latest release over HTTPS, verifies the Ed25519 signature on `SHA256SUMS`, then the archive checksum, before switching versions (see Release authenticity above). Never automatic without consent.
  - **Which release is latest:** the newest `dovet-<version>-<target>.tar.gz` named in the *signed* `SHA256SUMS` of the `releases/latest/download/` assets, so the version is as trusted as the checksum. A version that isn't newer than the installed one is never installed (a replayed old release can't downgrade); `dovet update` then says it is up to date.
  - **Install:** the archive unpacks into a scratch directory under `versions/` (entries outside `dovet/` and links are refused), must hold the executable, and is renamed to `versions/<v>/`; `current` then switches (POSIX: a new symlink renamed over the old one; Windows: the junction is swapped). Any failure before the switch removes the scratch directory and leaves `current` and `versions/` as they were.
  - **Rollback:** the file `previous` in the install directory names the version `current` pointed at before the last switch; `dovet update --rollback` points `current` back and writes the version it left, so running it twice returns. After an update only the new and the previous version stay on disk.

## Acceptance criteria
- [ ] **AC-ARCH-01** The compiled binary started in a directory containing `.env` (`X_TEST=1`) and `bunfig.toml` loads neither (`X_TEST` absent in child processes).
- [ ] **AC-ARCH-02** `dovet update` refuses an archive whose `SHA256SUMS` signature doesn't verify against the embedded key, and refuses a checksum mismatch; both leave the current version untouched.
- [ ] **AC-ARCH-03** Every release archive has a GitHub build-provenance attestation that `gh attestation verify` accepts for the release workflow.
- [ ] **AC-ARCH-04** The import-boundary check (`dependency-cruiser`) fails CI on a forbidden edge (e.g. `tools` importing `agent`).
- [ ] **AC-ARCH-05** Every release archive contains `THIRD_PARTY_NOTICES` listing each bundled package with its license text (and `NOTICE` file where one exists); the release build fails if a bundled package has no license.
