[DECISION-5] Built on vendored pi-tui. Default: `TuiMainScreen` (inline; native scrollback, selection and copy keep working). Option: `--fullscreen` / `ui.renderer: "fullscreen"` uses `TuiAltScreen` (no flicker on resize, app-owned scrolling, mouse support).

## Layout (inline mode)

```
  … scrollback: previous turns …

› fix the failing auth test                                  (user message)
  ▸ harness: Plan mode is now off                            (injected instruction, dim)
  ◆ thinking: checking how session tokens are validated…     (reasoning summary, dim, collapsible)
  ● Read src/auth/session.ts (212 lines)                     (tool call, one line, expandable)
  ● Edit src/auth/session.ts  +4 −1                          (expandable diff)
  ● Bash npm test  ✓ 7.9s                                     (expandable output)
  The test was failing because … (assistant text, markdown)
  ✓ 1 file · 1 command · $0.04 · checkpoint c7               (receipt line, expandable)

┌──────────────────────────────────────────────────────────────┐
│ > _                                                          │  (editor, multi-line)
└──────────────────────────────────────────────────────────────┘
 opus-5-5 · medium · manual · sandbox on · ctx 34% · $0.04 turn · $2.14/$5.00     (status bar)
```

**Status bar (always visible):** model, effort, permission mode, sandbox state (`on`/`weak`/`OFF` in red), taint (`⚠ tainted`), context gauge, turn cost, session cost / budget, retry status when retrying, `queued: 1` when input is queued.

## Append-only screen (inline mode)

pi-tui's inline renderer clears and fully re-renders when content **above the viewport** changes, which would wipe the user's scrollback [VERIFIED 2026-10-11, pi-tui README]. Rule: **in inline mode, anything that has scrolled above the viewport is immutable.** Only the live region (the streaming message, running tool lines, input, status bar) re-renders.
- Expanding an old tool call or receipt opens it in the **transcript viewer** (`Ctrl+O`, alternate screen, scrollable, searchable with `/`), not in place.
- Tool lines in the live region may still update (spinner → ✓); once scrolled off, their final state is what stays.
- **Width changes re-render only the live region.** Content already in the terminal's scrollback is left to the terminal's own reflow. Re-printing it on resize duplicates history in the scrollback, so the vendored pi-tui is changed accordingly [SPIKE-4].
- **Only completed blocks are committed to scrollback.** While streaming, the open block (a paragraph, list, table or code block) stays in the live region and is re-rendered there. It is printed into scrollback once, when complete. A half-streamed table therefore never leaves a stale render behind.

## Rendering rules

- Streaming text renders through the `Markdown` component with render caching; code blocks highlighted with shiki (lazy-loaded languages [SPIKE-6]).
- Width changes re-render the live region only (see above); fullscreen mode re-lays out from its own buffer.
- Tool calls render as one line with a status glyph (spinner → ✓/✗/⊘ denied/⏱ timeout). Enter or click expands while the line is in the live region (fullscreen mode: anywhere); older lines open in the transcript viewer.
- Diffs: unified diff with line numbers, red/green, word-level highlights for changed lines.
- Long tool output in expanded view is capped at 200 lines with "… N more lines (o to open in pager)"; the pager uses the alt screen temporarily.
- Colors: a theme with light and dark variants, auto-detected via `COLORFGBG`/OSC 11 query where supported [SPIKE-4]; `NO_COLOR` respected (monochrome, symbols only).
- **Dovet paints its own background** (owner decision, QUESTIONS Q8): the theme sets both the background and the default text color, so Dovet looks the same whatever the terminal's colors are. The detected light/dark only picks which variant starts (`ui.theme` overrides it).
  - While Dovet runs, the terminal's own default background and text colors are set to the theme's (OSC 11 and OSC 10, after the OSC 10/11 query has read the terminal's colors), so the whole window matches: rows Dovet hasn't drawn, the edges and the window padding too. The terminal's configured colors come back (OSC 110/111) on every path out, like the rest of the terminal state (see "Terminal I/O robustness"). Terminals that ignore OSC 10/11 still get the painted lines below.
  - Fullscreen mode paints the whole screen.
  - Inline mode also paints every line Dovet draws across the full width, including blank lines between blocks. After exit, the shell prompt is in the terminal's own colors again.
  - Every reset inside a line (`SGR 0`, `39`, `49`) is followed by the theme's colors again, so no text falls back to the terminal's colors mid-line; overlays use a slightly different shade of the background.
  - With `NO_COLOR`, or a terminal limited to 16 colors, no background is painted.
  - Lines already in the scrollback are not repainted when the terminal is resized (append-only screen); the terminal reflows them.

## Permission prompt

Behavior is specified in [permissions §6](permissions.md). Layout:

```
┌ Bash command ────────────────────────────────────────────────┐
│ Install zod                                                  │
│ npm install zod@4                                            │
│ Why: runs outside the sandbox (retry): effects not contained │
│                                                              │
│ Do you want to proceed?                                      │
│ ❯ 1. Yes                                                     │
│   2. Yes, and don't ask again for: npm install *             │
│   3. No                                                      │
│ Esc to cancel · Tab to add a comment                         │
└──────────────────────────────────────────────────────────────┘
```

- Keys: ↑/↓ + Enter or `1`–`3`; `Tab` on Yes/No opens the comment field; `Esc` = No.
- Edit/Write prompts show the diff; option 2 reads "Yes, allow all edits during this session".
- Network prompts show the host and the command that triggered it.
- The prompt is rendered in the live region (inline mode) or as an overlay (fullscreen).

## Question dialog

The dialog for AskUserQuestion is specified in [tools §4.3](tools.md): tabs per question, numbered options, Space for multi-select, an Other text field (Ctrl+G opens the editor), per-option notes with Tab, word-wrapped previews, and Esc to dismiss (the turn ends). In `ui.renderer: "plain"` each question is printed as a numbered list and answered by number or text.

## Task list

When the model keeps a task list ([tools §12](tools.md)), a compact panel above the input shows it: `◻ pending`, `▶ in progress` (with its `activeForm` text), `✔ completed`, and a `3/7` count. Ctrl+T toggles it. The current item also shows in the status line.

## Live command output

While a shell command runs, its tool line shows a spinner, elapsed time, and the **last 5 lines** of output (live tail, updated at most 10×/s). Ctrl+O shows the full live output. On completion the line collapses to `✓ npm test (7.9s)` / `✗ exit 1`.

## Rendering budgets

Model output can be pathological: tens of thousands of lines, deeply nested quotes, very long lines in highlighted code, unclosed strings or `<script>` tags, huge tables, base64 lines in diffs and unusual Unicode can freeze a renderer or use gigabytes. Dovet bounds the work instead of patching each case:
- **Incremental markdown:** only the open block is re-parsed on each delta; completed blocks are rendered once and cached, so streaming doesn't slow down as the reply grows.
- **Caps:**
  - highlighting gets ≤ 50 ms per block, and lines over 2,000 chars aren't highlighted;
  - lines over 5,000 chars are displayed cut in the middle with a marker (the full text stays in the transcript and log);
  - tables show at most 200 rows (`… N more rows`);
  - quotes and lists nest at most 10 levels deep (deeper levels render flat);
  - diff lines over 2,000 chars are cut.
- **Text width** is measured on grapheme clusters (`Intl.Segmenter`) with East Asian Width rules. Flags, joined emoji and combining accents wrap as single units, and a wide character never splits across the last column. RTL text is output in logical order and left to the terminal.
- **Frame coalescing:** at most 30 frames/s. If the terminal is slow or paused, intermediate frames are dropped and the latest state is drawn, so output never queues up behind the terminal.
- **Input first:** rendering runs in slices of ≤ 8 ms and keystrokes are processed between them, so Ctrl+C and typing always respond.
- **No idle work:** timers (spinners, elapsed time) stop when nothing is running; focus events are coalesced; no busy loops.
- **A rendering error never ends the session:** the error is logged and the screen fully repainted. After 3 errors within 10 s, Dovet switches to the plain renderer and says so. A fullscreen renderer that fails to start falls back to inline.
- **Readable prose:** `ui.maxProseWidth` (optional) caps prose width in wide terminals; tables and code keep the full width.

## Terminal output sanitization (security)

Text Dovet didn't author (model output, tool output, file contents, fetched pages, user input recalled from history, v0.2 hook and MCP output) is **never written to the terminal raw**. Escape sequences in it could set the window title, write to the clipboard (OSC 52), create deceptive links (OSC 8), or redraw parts of the UI to fake a prompt. Rules:
- **Control characters:** C0 controls other than tab and newline, and all C1 controls, are shown as visible escapes (`␛`, `^G`). ESC-introduced sequences (CSI, OSC, DCS, APC) are removed, except that **SGR color codes in command output** are parsed into Dovet's own style model and re-emitted, so colored test output keeps its colors.
- **Links:** Dovet creates OSC 8 hyperlinks itself, only from Markdown links and paths whose target is `http(s)` or a local `file` path, with no control or invisible characters and no network path. The visible text shows the real target when it differs from the link text.
- **Invisible and bidi characters** are made visible in permission prompts and diffs ([permissions §6](permissions.md)).
- **Child processes never get the terminal:** shell commands, `!` shell mode and (v0.2) hooks run with stdin from `/dev/null` and piped output, so they can't write to the screen or read keystrokes.

## Terminal I/O robustness

- **Capability detection by query, not by terminal name:**
  - synchronized output (mode 2026) via `DECRQM`;
  - the Kitty keyboard protocol via its query;
  - colors via OSC 10/11;
  - focus reporting.

  Each is used only if the terminal answers; overrides `ui.syncOutput` and `ui.keyboardProtocol`. Guessing from terminal names garbles terminals that don't match the guess. Synchronized output prevents flicker, including under tmux 3.4+.
- **Query replies never leak:** replies arriving late (slow SSH or browser terminals) are consumed by the input parser, never typed into the prompt. Outstanding replies are drained (≤ 100 ms) before exit, suspend or handing the terminal to an editor, so stray `22c` or `^[[?1;2c` text never appears at the prompt or in the shell afterwards.
- **Keyboard:**
  - the Kitty protocol is enabled only after the terminal answers and is popped on every exit, suspend and editor hand-off;
  - Shift with non-ASCII keys, capitals, non-Latin layouts and numpad all work;
  - legacy terminals' raw C0 controls (`Ctrl+]`, Ctrl+H as Backspace) are mapped;
  - two-key shortcuts wait 3 s for the second key, because tmux delays it;
  - bursts of type-ahead are applied in arrival order against the current state.
- **Bracketed paste:**
  - re-enabled on every focus-in and redraw, in case a program reset it;
  - a paste whose end marker never arrives ends after 1 s of silence, so input can't freeze;
  - focus and mouse reports interleaved in a paste are discarded;
  - newlines inside a paste, whether sent as `\n`, `\r`, Ctrl+J or Kitty key events, stay newlines;
  - overlapping or back-to-back pastes stay paste blocks, never typed text, which keeps the `<pasted_content>` marking correct;
  - Backspace deletes a collapsed paste as one unit;
  - paste blocks survive history recall, stash, Ctrl+C-clear (↑ restores the draft) and external-editor round trips without leaking markers.
- **Hardware cursor at the caret:** the terminal's real cursor is placed at the input caret (hidden when the caret is hidden), so IME composition windows for Chinese, Japanese and Korean input appear in place, and screen readers and magnifiers can follow. Completion triggers (`/`, `@`) also work after CJK punctuation without a space, and full-width digits are accepted in numbered choices.
- **Pasted images** are read without blocking, saved to the session's attachments directory (the model is given the path, so tools can use the file), resized like Read images, and turned into a placeholder instead of an error if corrupt.
- **Restoring the terminal:** raw mode, bracketed paste, the keyboard protocol, mouse tracking, focus reporting, the alternate screen, cursor visibility, the window title and the terminal's default colors are restored on **every** path out:
  - exit, Ctrl+C/Ctrl+D, and SIGINT from outside (an IDE stop button);
  - SIGTERM/SIGHUP, and a crash (before the crash report);
  - suspend (Ctrl+Z, including when launched through a wrapper such as `bunx`, by signalling the whole process group);
  - external-editor hand-off.

  A write error (`EIO`) because the terminal is gone triggers a fast exit, never a hang. After resume (`fg`), laptop wake or focus-in, the live region is fully repainted.
- **Clipboard (`/copy`, selection in fullscreen):** platform tools first when local (`pbcopy`, `wl-copy`/`xclip`/`xsel` with PRIMARY too, PowerShell on Windows and WSL). Over SSH, OSC 52, wrapped for tmux passthrough or loaded with `tmux load-buffer`. OSC 52 is never sent to terminals known to print it raw (VTE before 0.76, GNU screen). The confirmation names how to paste.
- **Window title and progress:**
  - the title is written only when it changes, using fixed-width spinner glyphs, so tab bars don't jitter;
  - it's restored on exit; `/rename` updates it; `ui.terminalTitle: false` disables it.
  - While a turn runs, the terminal progress indicator (OSC 9;4, shown in the tab or taskbar by Windows Terminal, Ghostty and iTerm2) stays on across tool calls.
- **Notifications inside tmux** use passthrough when allowed, and are never sent in a way that tears the display.

## Accessibility

- `ui.reducedMotion: true` (also when `NO_COLOR` or `TERM=dumb`) replaces spinners and live tails with static "running…" text updated once per second.
- Every state conveyed by color also has a symbol or word (✓ ✗ ⊘, "sandbox: off").
- `ui.renderer: "plain"`: a line-oriented output mode (no cursor movement, no redraws) usable with screen readers and in dumb terminals; prompts become numbered questions.

## Notifications

When a turn finishes, a permission prompt, question dialog or plan approval opens, or a budget pause happens, **and the terminal is not focused** (focus reporting `CSI ?1004h` where supported), Dovet emits a terminal notification (OSC 9 / OSC 777 where supported, else BEL). `ui.notifications: "auto" | "off" | "bell"`.

## Headless mode

`dovet -p "<prompt>"` (or prompt on stdin) runs one user turn (with all its tool rounds) and exits.

| Flag | Meaning |
|---|---|
| `--output text` (default) | Final assistant text to stdout; progress to stderr if TTY |
| `--output json` | One JSON object: `{schema, result, stopReason, incomplete, sessionId, receipt, usage, cost}` ([interfaces §10](interfaces.md)) |
| `--output stream-json` | NDJSON in the public `dovet.stream/1` schema ([interfaces §10](interfaces.md)), not raw internal events |
| `--allowedTools`, `--disallowedTools` | Extra allow / deny rules |
| `--permission-mode` | Permission mode. In headless, anything that would prompt is denied (`dontAsk` semantics) |
| `--budget` | Session budget |
| `--max-requests` | Override the per-turn request guard |
| `--resume <id>` / `--continue` | Continue a session |
| `--repair` | With `--resume`: continue in a repair epoch when the provider rejects the stored history ([event-log](event-log.md)) |
| `--no-session-persistence` | Don't keep the session log (temp dir removed at exit; no resume or rewind) |

**Exit codes:** 0 success (also when open tasks remain after the continuation limit; JSON has `incomplete: true`) · 1 error · 2 usage/config error · 3 loop guard stopped · 4 budget stopped · 5 refusal · 6 history rejected by the provider (repair with `--repair`) · 70 crash (report written) · 129 SIGHUP · 130 interrupted (SIGINT) · 143 SIGTERM.
