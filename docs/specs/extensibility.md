## MCP client [v0.2]

- **Spec target:** MCP **2026-07-28** (stateless: no `Mcp-Session-Id`, no initialize handshake; protocol version and capabilities in each request's `_meta`; Roots/Sampling/Logging deprecated) [VERIFIED 2026-10-10 via spec changelog and secondary coverage].
- **Library:** `@ai-sdk/mcp` (ADR-24). `createMCPClient` talks to both **modern** (2026-07-28, stateless discovery via `server/discover`) and **legacy** servers (the `initialize` handshake, with session persistence); transports: stdio (`@ai-sdk/mcp/mcp-stdio`), Streamable HTTP and SSE; OAuth through an `authProvider` (PKCE, Client ID Metadata Documents, issuer check); `mcpClient.tools()` returns AI SDK tool definitions, which Dovet wraps as `ToolDefinition`s without `execute` so every call goes through Dovet's permission flow [VERIFIED 2026-10-12, `@ai-sdk/mcp` 2.0.73 README and type declarations]. Fallback if a gap appears: `@modelcontextprotocol/client` (the official v2 client package).
- **Config:** read `.mcp.json` (Claude Code format, project) and `mcp` in Dovet settings. Project MCP servers require folder trust ([cli-config](cli-config.md)) and per-server approval on first use.
- **Transports:** stdio (child process, run under the sandbox where possible) and Streamable HTTP.
- **Auth (HTTP servers):** OAuth per the 2026-07-28 spec: Protected Resource Metadata discovery (RFC 9728), Resource Indicators (RFC 8707, required for clients), issuer (`iss`) validation (RFC 9207), Client ID Metadata Documents preferred over Dynamic Client Registration, `offline_access` for refresh tokens. Tokens in the OS keychain.
- **Context cost control (mandatory):** MCP tool schemas are **not** all loaded up front. On Anthropic: declare MCP tools with `defer_loading: true` plus the tool-search tool (`tool_search_tool_bm25_20251119`); never defer every tool (400) [VERIFIED]. Other providers: Dovet's own `SearchTools` tool returns schemas on demand, which are then added via a new epoch or `tool_addition` where supported. On Anthropic, the `inline-tools-2026-09-15` beta adds tools mid-conversation without invalidating the cached prefix [VERIFIED 2026-10-11]. Evidence: three MCP servers consumed 143k of a 200k window before the first message.
- **Trust:** MCP results are **tainting** unless the server is marked `trusted: true` by the user.
- **v0.1 constraint:** the tool registry must support tools from external sources with namespaced names (`mcp__<server>__<tool>`), and the transcript builder must support deferred tools.

## Skills [v0.2]

- Read `SKILL.md` folders from, in this order (first `name` wins): project `.dovet/skills/`, `.agents/skills/`, `.claude/skills/`; user `<config>/skills/`, `~/.agents/skills/`, `~/.config/agents/skills/`, `~/.claude/skills/`. `.agents/skills/` and `~/.agents/skills/` are where the `skills` CLI (`npx skills add …`) installs for Codex, Cursor, Gemini CLI, Pi and other agents, and `~/.config/agents/skills/` is its "universal" global location [VERIFIED 2026-10-12, `skills` 1.7.2 README], so skills installed for other agents work in Dovet without copying. Symlinked skill folders (the CLI's default install method) are followed, within the same trust rules as the folder they're linked from.
- Frontmatter: `name` (lowercase, hyphens) and `description` required; `metadata.internal: true` skills are skipped.
- Only names + descriptions go in context (in the system prompt at epoch start); the model reads the full SKILL.md with the Read tool when relevant (progressive disclosure).
- **v0.1 constraint:** the system prompt renderer has a "capabilities index" section that can list skills.

## Hooks [v0.2]

- **Events** (same names as Claude Code's, so existing hook scripts work): `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `Stop`, `SubagentStop`, `PreCompact`, `InstructionsLoaded`. Input/output JSON shapes follow Claude Code's hooks reference [SPIKE-27].
- A hook is a command receiving JSON on stdin and returning JSON (decision: allow/deny/ask, optional message, optional additional context which is injected as a mid-epoch instruction, never as a history edit).
- Hooks run sandboxed with a timeout (default 30 s); project hooks require folder trust.
- **Loop caps:** a Stop hook that blocks 8 times in a row ends the turn with a warning; hooks that time out are reported as timeouts, never as a user rejection.
- **Files a hook changes** (format-on-save `PostToolUse` hooks) are re-hashed into read-state after the hook, so the next Edit/Write doesn't fail as stale.
- **v0.1 constraint:** the policy engine's decision pipeline has an extension point between rules and the mode default.

## Subagents [v0.2]

- A `Task` tool spawns a child session with its own epoch, restricted tools (configurable; read-only by default) and a budget slice. The child's final text returns as the tool result; its log is a separate session file linked by `session.fork`-style parent references.
- **v0.1 constraint:** `Runtime.openSession` must support several sessions per process (tested in M1); the `Task` tool receives a `spawnChild` capability through `ToolContext` (ADR-26), never by importing `agent`.
- **Spawn cap:** at most 200 subagent spawns per session by default (runaway delegation loops).
- Use only for context isolation and true parallelism (evidence: elaborate multi-agent graphs aged badly).
- Caching: children reuse the parent's exact system prompt + tools where possible; the first child's request is sent before others start (a cache entry is readable only after the first response begins streaming) [VERIFIED].

## ACP server [v0.2]

- `dovet acp` speaks the Agent Client Protocol over stdio via `@agentclientprotocol/sdk`, so Zed, JetBrains and other ACP editors can use Dovet. The same server lets AI SDK apps drive Dovet through `@ai-sdk/harness-acp`; no separate harness package is built. The ACP layer is another consumer of `AgentEvent`s plus the command API ([architecture](architecture.md)); no agent logic in it.

## LSP diagnostics [v0.2]

Language-server diagnostics fed back to the model after edits catch type errors without a build step.
- `LSP` tool: definition, references, hover/type, document symbols, workspace symbol search, implementations, call hierarchy.
- After each Edit/Write, diagnostics (errors and warnings) for the changed file are appended to the tool result, capped at 20 entries.
- Servers are configured per language in settings (`lsp.<language>: { command, args, filetypes }`), started lazily, run outside the sandbox but only after workspace trust; the user installs the server binaries.
- **v0.1 constraint:** tool results must support appended post-processing content (diagnostics) without changing the tool contract.

## Background shell tasks and Monitor [v0.2]
- `Bash.run_in_background: true` starts a task (Bun's built-in PTY) and returns a task id + output file path; `/tasks` lists and stops them; tasks end when the session ends (interactive) or after 30 min (headless, max 2 h).
- A foreground command that hits its timeout moves to the background instead of being killed.
- `Monitor`: runs a command and feeds new output lines back to the model as events.
- **v0.1 constraint:** process management goes through one `ProcessManager` in `platform` that already tracks process trees per session.

## NotebookEdit [v0.2]
Cell-level edits of `.ipynb` (replace/insert/delete by cell id), keeping outputs and metadata; refuses non-UTF-8 notebooks.

## Custom slash commands [v0.2]
Markdown prompt templates in `.dovet/commands/` and `.claude/commands/` (`$ARGUMENTS`, `$1…`, frontmatter `description`, `allowed-tools`), shown in the `/` palette. Merged with skills (a skill can be invoked as `/<name>`).

## Later candidates [v0.3]

Git worktree isolation for parallel sessions; plugins (bundles of skills + hooks + MCP config); code mode via `@ai-sdk/code-mode` (tool calls composed as code in a QuickJS sandbox, each call still going through Dovet's permission flow; measured to cut steps ~42% and tokens ~56% in a 2026 study); provider-native compaction and context editing as opt-in options ([context §6](context.md)).
