The event log is the single source of truth for a session. Every other view (the transcript sent to the model, receipts, `/why`, resume, rewind, cost) is derived from it. [DECISION-4]

## Locations

| What | Path |
|---|---|
| Session log | `<data>/projects/<projectId>/sessions/<sessionId>.jsonl` |
| Blob store | `<data>/blobs/<sha256[0..2]>/<sha256>` |
| Session metadata sidecar | `<data>/projects/<projectId>/sessions/<sessionId>.meta.json` (disposable cache) |
| Offloaded tool output | `<data>/projects/<projectId>/sessions/<sessionId>/outputs/<eventId>.txt` |
| Debug request bodies (opt-in) | `<data>/projects/<projectId>/sessions/<sessionId>/requests/<eventId>.json` |

`<data>` is defined per OS in [specs/cli-config.md](cli-config.md). `projectId` = first 16 hex chars of SHA-256 of the canonical absolute **project root** path ([cli-config](cli-config.md)) (lowercased on Windows and on case-insensitive macOS volumes [SPIKE-10]), plus a readable suffix: `<basename>-<hash16>`.

## Event envelope

Every line is one JSON object (UTF-8, no BOM, `\n`-terminated). U+2028 and U+2029 are always written escaped (`\u2028`), because some line readers (e.g. Python's `splitlines`) treat them as line breaks. The same rule applies to `--output stream-json`:

```ts
type EventEnvelope = {
  v: 1;                    // schema version
  id: string;              // ULID; monotonic within a session
  ts: string;              // ISO-8601 UTC, ms precision
  session: string;         // session ULID
  epoch: number;           // compaction epoch, starts at 0
  turn: number | null;     // user-turn counter; null for session-level events
  type: EventType;
  core: boolean;           // see "Core vs optional events"
  data: unknown;           // validated by the zod schema for `type`
};
```

**Determinism rule:** `id` and `ts` are metadata. They are **never** rendered into prompts (principle 7).

## Event types (v0.1)

| type | data (key fields) | Written when |
|---|---|---|
| `session.start` | harness version, OS, arch, shell, cwd, workspace roots, git (is repo, branch, HEAD sha), provider, model, effort, permission mode, sandbox state, **hashes of the system prompt template, tool definitions and instruction files**, resolved config snapshot (secrets redacted) | Session created |
| `epoch.start` | epoch number, reason (session-start / compaction / model-switch / thinking-config-change / repair), provider, model, **the exact rendered system prompt text and exact serialized tool definitions, stored inline in the event** (not as blobs, so they can never be garbage-collected while the log exists; ~10–30 KB per epoch), thinking config, prompt version | Every epoch start. **Resume and replay use these stored bytes, never a re-render.** Otherwise upgrading Dovet (a changed template or tool description) would silently change the prefix of a resumed session, breaking the prompt cache and invalidating reasoning blocks |

| `session.fork` | parent session id, parent event id | `/rewind` creates a fork |
| `instructions.loaded` | list of files (path, sha256, bytes, lines, trigger: launch / lazy-subdir / path-rule / changed / import), warnings, optional `dropped` (paths no longer loaded; resume forgets them, QUESTIONS Q74) | Session start; lazy loads; change detection |

| `permission.request` | call id, kind (tool/path/network/command), details, rule candidates | Policy needs a decision |

| `tool.result` | call id, status (ok/error/denied/interrupted/timeout), output text (≤ 30,000 chars) + offload path if larger, `media` (images and PDFs: blob, media type, bytes, [tools §1](tools.md)), exit code, duration ms, sandbox violations; for WebSearch: `search` (backend, calls, price if set, [tools §10](tools.md)); for Read: path, range and SHA-256 of the bytes returned (drives re-read dedup, [tools §1.5](tools.md)) | Tool finished |

| `compaction` | from epoch, to epoch, trigger (auto/manual/context-exceeded/partial), kind (summary / mechanical-fallback), the exact first message of the new epoch (retained user messages, summary text, Dovet facts), whether the summary request was reduced, tokens before/after, summarizer usage | Epoch change |
| `system.injected` | text, reason (instructions changed, mode changed, reminder), delivery (system-message/reminder-block) | Harness appended an instruction mid-epoch |

| `taint.change` | tainted (bool), source (tool call id, URL, MCP server) | Taint set or cleared |
| `user.shell` | command, exit code, output (limited as Bash), duration | `!` shell mode ([tui](tui.md)) |
| `budget.event` | kind (warn/limit-reached/extended), scope (turn/session/day/tokens), spent, limit | Thresholds crossed |
| `receipt` | the full receipt object ([receipts-budgets](receipts-budgets.md)) | Turn ends |
| `turn.end` | turn, reason (end_turn/interrupted/cancelled/error/budget/refusal/max-turns/crashed), duration. `cancelled` = interrupted before any model output: that turn's user message is excluded from the transcript ([agent-loop](agent-loop.md)) | Turn ends |
| `settings.change` | key, old, new, source | `/model`, `/effort`, `/mode`, etc. |
| `session.end` | reason | Clean exit |

**Core vs optional events:** every event type is classified. **Core** events affect transcript construction, permissions, budgets, files or tool execution (`session.*`, `epoch.start`, `user.message`, `model.request`, `model.response`, `tool.call`, `tool.result`, `permission.*`, `file.change`, `checkpoint`, `compaction`, `system.injected`, `taint.change`, `user.shell`, `budget.event`, `settings.change`, `plan.*`). **Optional** events are informational (`receipt`, `instructions.loaded`, `shell.snapshot`, `turn.end`). The envelope carries `core: boolean`.
- Unknown **optional** event → skipped with a warning.
- Unknown **core** event, unsupported schema version `v`, a missing essential blob, or an invalid state transition (e.g. a `tool.result` with no `tool.call`, a permission decision for an unknown request) → the session opens **read-only** with the exact reason; it is never silently rebuilt.
- Schema changes that alter existing fields bump `v` and add a reader for the old version.

## Writer rules

1. **Single writer per session file.** On open, create `<session>.lock` with exclusive-create (`open(path, "wx")`), containing PID, hostname and start time. The writer **touches the lock file's mtime every 30 s** (heartbeat). A lock whose mtime is older than 2 minutes is stale and may be taken over. This avoids PID-liveness checks (PID reuse on Windows, containers, network filesystems). A second process opening the same session gets read-only mode and a warning.
2. **Append-only.** The file is only ever opened in append mode. No rewrites, no truncation, ever.
3. **Buffered writes.** Events are queued in memory and flushed: on `user.message` (so a prompt is never lost, [checkpoints](checkpoints.md) "Rewind"), on `turn.end`, on `permission.request` (so a crash while waiting loses nothing), every 2 seconds while streaming, and on exit. `fsync` happens on `user.message`, `turn.end` and `session.end` only.
4. **Crash tolerance.** On read, a final line that fails to parse (partial write) is ignored and reported once. Any other unparseable line is a corruption error: show its line number and continue in read-only mode.
5. **Size guard.** Any string field over 256 KB inside an event (e.g. the `content` of a large Write call in `tool.call`, a huge raw model output) is moved to an **essential** blob and replaced by `{ "$blob": "<sha256>", "bytes": N }`; readers resolve it transparently. A single serialized event over 1 MB after this step is a bug. Tool output in `tool.result` is capped at 30,000 chars (full output in offload files).
6. **File permissions.** Logs, blobs, offload files, snapshots and the budget ledger contain code and command output. On POSIX, `<data>` and everything under it are created with mode `0700` (dirs) / `0600` (files); Dovet warns at startup if they are group/world-readable. On Windows, data lives under `%LOCALAPPDATA%`, which inherits the user-only profile ACL; Dovet doesn't loosen it.
7. **Disk-write budget test.** A CI test runs a scripted 50-turn session and asserts total bytes written (log + blobs + sidecars) stay under a fixed budget (initially 20 MB) and that no file except the `.meta.json` sidecar is rewritten in place.

**Decided while building (QUESTIONS Q22):**
- Each event's `data` schema is added by the task that first writes that event; until then the envelope is validated and `data` is any JSON. Event types and their core/optional class live in `src/schema/events.ts`.
- Redaction at write time: values of 8 or more characters from env vars whose names contain KEY, TOKEN, SECRET, PASSWORD, PASSWD, PASSPHRASE, CREDENTIAL or AUTH, plus every resolved credential; each occurrence in any string of an event becomes `[redacted]`, and a `Secret` object is written as `[redacted]`.
- A data object with a `$blob` or `$lit` key is written wrapped as `{ "$lit": … }` and unwrapped on read, so model-written input can never make a session unreadable.
- Torn last line: the writer appends `\n` and a `session.resume` event `{ reason: "crash-repair", tornLine: N }`. The reader accepts an unparseable line in the middle of the file only when the very next event is that repair naming its line, and reports it as a warning. Any other invalid event opens the session read-only.
- The startup disk check covers `<data>`, `<data>/projects`, `<data>/blobs`, this project's session folder and the files directly in it, not a full walk of `<data>`.
- The reader checks lines, types, versions and blobs; event-order invariants are checked by the transcript builder, which already walks events in order. `close()` fsyncs even without `session.end`.

## Blob store

- Content-addressed by SHA-256 of the raw bytes; written as temp file + rename; never modified.
- Used for: file contents before/after edits (checkpoints) and user attachments (images, files). Large tool outputs are **not** blobs; they go to the session's offload files (see Locations).
- **Blob classes and GC invariant:**
  - **Essential** blobs (user attachments; any blob a transcript replay needs) are kept **as long as any retained session log references them**. GC traces references from **all** retained logs, never only recent ones. A session advertised as resumable is always fully resumable.
  - **Rewind-only** data (checkpoint before/after file contents, snapshot objects) may expire after `retention.days` (default 30). A forked session's references count like the parent's: data is kept while any retained session references it. Expiry is recorded per session (`rewindAvailableUntil` in the sidecar); `/rewind` shows "expired" instead of failing. Rewind availability and resumability are separate capabilities.
  - `retention.deleteSessions: true` deletes whole sessions older than the retention period (log + sidecar + their essential blobs once unreferenced).
  - GC runs with the data-directory GC lock and skips any session whose lock heartbeat is fresh (active sessions are never collected under).
  - If an essential blob is nevertheless missing (disk damage, manual deletion), resume opens the session **read-only** and names the missing item.

**Decided while building (QUESTIONS Q81):**
- A session's age is the last write to its log. Rewind data expires when that is older than `retention.days`; GC then writes `rewindAvailableUntil` (last write + `retention.days`, ISO time) into the sidecar of every session that isn't running, and `/rewind` shows "expired" for a session whose time has passed (`rewindExpired`). A sidecar rebuilt from the log loses the field until the next GC.
- A reference is a `$blob` value, a `{ store: "blob", id }` ref, or a `before`/`after` hash in `file.change` and `checkpoint` events. A log line that doesn't parse keeps every 64-hex string in it as essential.
- Blobs and snapshot objects younger than one hour are never removed (their event may not be logged yet), and storing a blob that already exists refreshes its age, so a session about to log it can't lose it to a GC that is already running.
- Offload files and debug request bodies are removed by age (`retention.outputsDays`) per session; a Read of a missing path under a session's `outputs/` or `requests/` folder answers `Full output expired (kept N days).`
- `dovet sessions list|delete` cover every project in `<data>`; `delete` runs GC afterwards so the blobs only those sessions used go too. A session whose lock is fresh is never deleted. `deleteSessions` and the GC skip it the same way.
- Startup: the data-size warning (at most once a day, stamped in `<data>/size-warning.json`) and a background GC run before the turn and are stopped when it ends. A GC that fails prints a line; it never stops the turn.

## No database

There is no database or second store (ADR-4): two stores that must stay in sync are a classic bug source. Everything below is derived from the logs and can be rebuilt.
- **Session list** (`/resume`): read the project's session directory; each session's metadata comes from its `session.start` line plus a small sidecar `<session>.meta.json` (title, updated, turns, cost) rewritten atomically at each `turn.end`. The JSONL stays append-only; the sidecar is a disposable cache, rebuilt from the JSONL if missing or stale.
- **Daily spend:** the per-day reservation ledger ([receipts-budgets](receipts-budgets.md) §B.5), not sidecars.
- **Search** (v0.2): ripgrep over session files.
- Session **title**: the first 60 chars of the first user message (no model call, principle 3). An optional `titles.model` setting can generate titles with a cheap model, shown and counted.
- If listing ever exceeds 200 ms with real data, add a rebuildable index (ADR), never a second source of truth.

**Session sidecar fields (QUESTIONS Q22):** `id`, `title` (first 60 characters of the first user message, trailing spaces removed), `created` and `updated` (first and last event times), `turns` (count of `turn.end`) and `bytes` (log size when written). A sidecar whose `bytes` differs from the log's size is rebuilt. Cost joins once receipts exist.

## Resume

`dovet --resume [id]` / `/resume`: read the JSONL **as a stream, line by line** (never the whole file into memory), validate every event, and rebuild the session state (current epoch, transcript, settings, taint, budgets, read-results index for dedup). If the provider or model in config differs from the session's, ask whether to continue with the session's model or switch (switching drops provider-opaque reasoning, see [providers](providers.md)). Dovet never auto-resumes a session on launch; only `--resume`/`--continue`/`/resume` do. (Auto-resuming an oversized or damaged session would make every launch hang or fail.)

**Cold large sessions:** when the resumed epoch is large and its cache has certainly expired, the first request is a full uncached re-read. Resume shows its estimated cost and offers `/compact` first. Read-state and the read-results index are rebuilt **only from this session's log**; nothing is carried over from the previously open session.

**What resume restores, and what it doesn't change:** the permission mode (incl. `plan`), taint, working directories, budgets and **cost totals** come back exactly from the log. The current epoch's **stored** system prompt and tool definitions are replayed **even if settings now differ** (a removed tool, a changed `--allowedTools`, a new Dovet version). Differences are listed at resume, and the user chooses to apply them in a new epoch now or at the next epoch boundary. A changed tool list breaks the cache and drops reasoning. Calls to a tool that the current settings now forbid are denied by policy as usual; the tool's definition stays in the epoch.

**Self-healing a damaged log (no edits):** if validation stops at event N (a malformed line, an invalid state transition), the session opens read-only with the reason **and** offers `Continue from the last valid point`. That forks a new session at the last complete turn before N, like `/rewind`, so the user keeps their work. The fork leaves the damaged file untouched for inspection.

**Fast path:** the sidecar stores the byte offset and event id of the latest `epoch.start`, plus a state snapshot at that point (mode, settings overrides, taint, budget totals, turn counter). Resume verifies the event id at that offset, then streams only from there. A missing or mismatched sidecar → full streaming scan (slower, same result).

**Crash recovery (applied on resume, appended as new events, never by rewriting):**
- `tool.call` without `tool.result` → a `tool.result` with status `interrupted`: `Not run or not finished: Dovet exited before this tool completed. Check the current state before retrying.` (Every `tool_use` needs exactly one `tool_result`; without it, every request of the resumed session fails with 400.)
- `permission.request` without a decision → decision `no` with source `interrupted`, plus the result above.
- `model.request` without `model.response` → nothing to replay (the response was never appended).
- A turn without `turn.end` → `turn.end` with reason `crashed`, then a receipt built from what the log shows.
- File changes made by a shell command that was running at the crash aren't attributed; the next snapshot diff shows them as `via: bash, byCommand: unknown`.

**Never stuck: replay normalization first, then the repair epoch.** Known-bad replayed content (empty text blocks, API-rejected blocks) is normalized away deterministically at render time ([providers §3](providers.md)). For anything else: Dovet itself never writes content the APIs reject: no empty or **whitespace-only** text blocks (Dovet's `submit` ignores whitespace-only input), no assistant turns with only reasoning, no non-text tool output (objects or numbers from tools are serialized to text), and no padding blocks. A pre-request **transcript validator** asserts this every time (an `InvariantViolation` if Dovet broke it). Even so, a provider may reject replayed history, for example after an API change, a provider bug, or a model's own empty block (empty text or thinking blocks in saved history can make every resumed request fail). When a request fails with a non-retryable `invalid_request` that the adapter classifies as **history-related**, Dovet offers **"Repair: continue in a new epoch built from the normalized transcript"**:
- the new epoch drops provider-opaque reasoning, empty blocks and unpaired items, exactly like a model switch (epoch reason `repair`);
- it costs one cache miss and is shown and logged;
- headless runs exit with code 6 and the hint `dovet --resume <id> --repair`.
- Nothing in the log is edited.

**Ephemeral sessions:** `--no-session-persistence` (headless; same flag name as Claude Code, for script compatibility) writes the log to a temp directory removed at exit (no resume, no rewind). The daily budget ledger is still written.

**Decided while building (QUESTIONS Q50):**
- An interrupted permission prompt is recorded as `{requestId, decision: "no", source: "interrupted"}`; a crashed turn's minimal receipt is `{turn, reason: "crashed", cost: {sessionUsd}}` until the full receipt exists.
- The resume scan validates every line's envelope, version and core/unknown type but doesn't resolve blob refs; full blob validation stays in `readSession`. The sidecar holds the byte offset and event id of the latest `epoch.start` plus the state just before it (`mode`, `taint`, `turn`, `costUsd`, `provider`, `model`).
- A provider error is history-related when it is a non-retryable `invalid_request` whose message names history, replay, transcript, tool results, prefix, messages or blocks.
- A fork copies raw lines through the `turn.end` of the last complete turn, stopping at a corrupt line, a later turn or a later epoch; the original is never touched. `--no-session-persistence` writes the log to a temp folder removed at exit.

## Disk use

Session logs can grow to gigabytes each, and hundreds of GB in total, when compaction history and raw tool output are stored repeatedly. Dovet:
- never stores the transcript twice: a compaction stores the summary only; epoch headers are ~10–30 KB; tool output in the log is capped at 30,000 chars;
- **offload files** (full tool outputs) and debug request bodies are **ephemeral**: deleted after `retention.outputsDays` (default 7). A later Read of an expired offload path says `Full output expired (kept 7 days).`;
- shows the data directory's size in `/status` and warns once per day at startup when it exceeds `retention.warnAtGB` (default 10), naming the largest sessions and the command to prune them;
- `dovet sessions delete --older-than <days>` / `--larger-than <size>` and `dovet gc` reclaim space; GC runs in the background at startup with the rules above.

## Acceptance criteria

- [ ] **AC-LOG-01** Killing the process with SIGKILL mid-stream and resuming loses at most the in-flight model response; the session continues with a valid transcript.
- [ ] **AC-LOG-02** Replaying a session log through the transcript builder reproduces byte-identical request bodies (compared via the `model.request` body hash).
- [ ] **AC-LOG-03** The disk-write budget test passes.
- [ ] **AC-LOG-04** Opening the same session in two processes: the second is read-only and says so.
- [ ] **AC-LOG-05** Deleting every `.meta.json` and listing sessions rebuilds identical metadata from the JSONL files.
- [ ] **AC-LOG-06** No secret from the env or config appears in any event (test plants fake secrets and greps the log).
- [ ] **AC-LOG-07** A Write of a 3 MB file stores its content as an essential blob reference in `tool.call`; replay reproduces the identical request.
- [ ] **AC-LOG-08** On POSIX, `<data>` dirs are 0700 and files 0600; startup warns if permissions were loosened.
- [ ] **AC-LOG-09** An unknown core event type opens the session read-only with the reason; an unknown optional event is skipped with a warning.
- [ ] **AC-LOG-11** SIGKILL during a running Bash call, then resume: the call gets the interrupted result, the turn gets `turn.end: crashed`, and the next request is accepted by the provider.
- [ ] **AC-LOG-12** A fixture where the provider rejects replayed history (fake 400 classified history-related) offers the repair epoch; after repair the next request succeeds; the log has no rewritten lines.
- [ ] **AC-LOG-13** A 500 MB synthetic log resumes in < 2 s with its sidecar and in < 30 s without, with peak memory < 300 MB.
- [ ] **AC-LOG-14** Offload files older than `retention.outputsDays` are removed by GC; reading one returns the expiry message; `<data>` over `warnAtGB` triggers the startup warning.
- [ ] **AC-LOG-15** SIGKILL during a parallel batch (3 reads + 1 Bash) and resume: completed results are kept, the unfinished ones get interrupted results, no turn is lost; mode `plan` and cost totals are restored; a resume with a narrower tool setting still sends the stored tool definitions byte-identically.
- [ ] **AC-LOG-16** A log with a corrupted line in turn 7 of 10 opens read-only and offers a fork from turn 6; the fork continues normally and the original file is unchanged.
- [ ] **AC-LOG-10** GC never removes an essential blob referenced by any retained log; expired rewind data shows "expired" in `/rewind`.
