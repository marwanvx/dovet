# Open Questions & Spikes

Every unverified assumption in the specs is listed here, and each one is cited (`[SPIKE-n]`) at the spec section it affects. Each spec's "Before you build" box repeats its spikes with their fallbacks, so an agent sees them without opening this file. A **spike** is a small, time-boxed experiment (usually ≤ 1 day) that produces a written answer and, if needed, a spec/ADR change. Features marked with a spike must not be built until it's resolved.

Last updated: 2026-10-12.

## Product decisions (owner)

| # | Question | Decision |
|---|---|---|
| Q1 | Product name | **Dovet** (command `dovet`), decided 2026-10-12 |
| Q2 | License | **MIT** (ADR-29) |
| Q3 | Refusal fallback on by default? | **Off**; visible opt-in (`refusal.fallback`) |

| Q7 | Default session budget | **None**; costs are always shown live, and `/budget` sets a limit ([receipts-budgets](../specs/receipts-budgets.md)) |
| Q8 | Windows sandbox | **MXC → one-time admin setup → none with more prompts**; WSL2 gets the Linux sandbox (ADR-6) |
| Q9 | Code signing | **No paid certificates until the project has income**; free SignPath signing for Windows |
| Q10 | Model layer | **Vercel's AI SDK** for every provider, with Dovet's own log format so it can be replaced per protocol on evidence (ADR-30) |
| Q11 | Which providers first | **None first:** every models.dev provider is available through the registry, treated the same; per-provider code only where data isn't enough ([providers](../specs/providers.md)) |
| Q12 | Who merges PRs | **The build loop merges** after a fresh review and green CI on all three OSes; changes to decisions (ADRs, roadmap, product decisions) wait for the owner ([build loop](../workflow/build-loop.md)) |
